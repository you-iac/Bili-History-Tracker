# 本地档案、数据管理与用户自选云盘

状态：数据管理与云盘仍为需求设计。当前 Agent 已保存本地关注、服务器地址和公共缓存，以及扫描检查点/受保护 Cookie，并提供扫描导出；仍不等于完整档案管理或备份。现有能力见 [本地关注接入](client-library.md) 与 [客户端发现](client-discovery.md)，共同需求见 [客户端说明](../client/README.md)。

## 数据归属与身份

用户拥有并管理自己的数据档案，Agent 提供数据管理和操作控制。档案可以包含本地生成的稳定标识、名称、关注列表、偏好和任务信息；它表达本地数据归属，不代表公共服务器验证过的登录身份。

默认一个 Agent 使用一个本地档案，无需先注册或设置账号密码；可按需要增加本地解锁保护。多人共享一个实例时仍需真实的本地认证与权限隔离，档案切换和备份密码不能代替共享实例的访问控制。

| 部分 | 职责 |
|---|---|
| 公共跟踪服务器 | 共享 UP/视频资料、指标和历史；不接收私人档案、云盘凭据或备份，不参与恢复 |
| 本地 Agent | 管理档案与文件，导入导出、备份恢复，按用户配置直接连接个人存储 |
| 用户自选云盘/存储服务器 | 保存用户启用同步的数据；账号、容量、授权和保留策略由用户管理 |

公共服务器访问凭据、B站 Cookie、云盘凭据和档案解锁密钥分别管理。用户可在不同设备恢复自己的档案，不需要因此在公共跟踪服务器建立个人账户。

## 管理界面

增加“数据管理”入口，与关注库、下载任务和连接设置配合，提供：

- 查看档案、数据目录、占用空间，以及关注、扫描、任务、缓存和文件的分类统计。
- 创建或选择档案，修改名称，查看当前数据来源；导入/切换不自动执行远程采集申请或下载。
- 导出关注与可迁移设置，生成完整数据备份，查看备份范围、版本、大小和时间。
- 导入前预览与校验，选择合并或恢复；恢复前生成回滚点，失败保留原档案。
- 按类别清理缓存、任务记录或数据；清理索引、删除媒体和删除云端备份分别操作，不能互相隐含。
- 配置备份目录、计划、保留数量；未来提供云盘连接、测试、立即备份、暂停、重试和恢复选择。

删除与覆盖操作展示具体范围并由用户确认。删除个人关注或本地数据不停止公共跟踪，也不默认清理云端已有备份。

## 数据范围

| 数据 | 本地管理与备份策略 |
|---|---|
| 档案标识/名称、UP/视频关注、标签、显示与下载偏好 | 默认可迁移，纳入数据备份；云盘同步需用户启用 |
| 扫描检查点、申请结果、下载任务与文件索引 | 可选纳入；恢复后重新核验公共状态、文件和平台续页，不直接重放旧任务 |
| 公共记录缓存、临时文件、诊断日志 | 默认不纳入，可重建或按需另行导出，日志不含密钥 |
| 视频、评论与弹幕文件 | 默认不随档案备份；未来允许单独选择媒体备份及容量策略，索引备份不代表文件已备份 |
| B站 Cookie、服务访问凭据等敏感信息 | 默认不导出、不上传；用户明确选择时才进入独立加密凭据备份 |
| 云盘连接凭据、备份解密密钥、本地会话和设备身份 | 云盘凭据与解密密钥保留本机，设备会话不迁移；新设备先自行连接云盘，再恢复档案并重新授权 |

“私人数据不上传服务器”指不上传项目公共跟踪服务器。用户启用个人云盘后，所选数据会从 Agent 直接发送到该存储，不经公共服务器中转；界面明确目标、范围及最近结果。

## 备份与恢复

先提供可手动搬运的、带版本的数据备份包，再将同一备份能力接入自动计划和存储适配器。备份记录格式版本、档案标识、创建时间、设备来源、数据范围和完整性校验；云端载荷由 Agent 在上传前加密，解密密钥由用户保管，不与备份一同明文上传。

通过一致性导出或快照产生备份，不将运行中的数据目录或数据库直接交给通用网盘实时双向同步。当前本地主要是 JSON 文件；将来若采用 SQLite，使用受支持的快照方式，参考 [SQLite 在线备份](https://www.sqlite.org/backup.html)。

恢复在临时位置解密、校验和迁移，完整成功后才替换或合并到档案；不接受越界文件路径，拒绝不支持的格式与损坏备份。合并关注按平台、目标类型及标识去重；覆盖前保留回滚点，不能无提示用旧版本覆盖新数据。

设备专属路径、Cookie、临时媒体地址和任务执行状态在新设备重新核验。没有媒体文件时标为缺失，远程申请先对账，任务等待用户确认或已配置策略；恢复档案不自动发起采集申请、下载或删除文件。

## 凭据迁移

本机凭据保护与跨设备备份是两种能力。现有 Windows `cookie.protected` 使用用户级 DPAPI，不能将复制此文件当成通用跨设备登录恢复；Windows 通常要求同一登录身份和计算机才能解密，见 [Microsoft DPAPI 说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

如用户选择备份敏感凭据，由原设备在授权后读取，并使用用户持有的可迁移密钥重新加密；目标设备解密后使用自身的系统保护重新保存。不能原样同步 DPAPI 文件并宣称异机可用。恢复的 Cookie 仍可能已失效，需验证或重新导入。

加密格式与密钥管理在实施时选用成熟方案；用户丢失解密密钥时，公共服务器无法找回私人备份。自动备份需要的密钥使用本机安全存储，不要求每次手动输入，也不随日志或云盘明文配置导出。

## 云盘自动备份与同步

未来以存储适配器连接用户指定的云盘或自托管存储，具体协议及供应商在实现阶段确定。云盘认证直接发生在 Agent 与用户存储之间，不依赖公共服务器账户。

首个云盘阶段提供自动上传版本化备份、列出历史版本和用户选择恢复；先不承诺多个设备实时双向编辑同一份活动数据库。支持连接测试、启停、手动立即执行、时间计划、状态、失败原因、限速与保留策略；关闭同步仍可完整使用本地数据。

上传使用独立版本及完成标记，未完整上传不能成为可恢复版本；断网重试不覆盖最后一次成功备份。每设备保留来源与版本信息，并发备份独立保存；恢复前预览差异，不静默选择“最后写入者”。删除本地资料不自动传播为删除全部云端历史，删除云端历史也不停止服务器公共采集。

将来实现真正的双向同步时，另行设计基准版本、逐项变更与删除标记、冲突保留和人工合并；不能只按文件修改时间覆盖，否则可能丢失另一设备的修改或恢复已删除的关注。

## 实施顺序与验收

1. 建立本地档案与数据分类，提供数据概览、关注/设置导入导出和清理控制。
2. 实现一致性备份、加密、校验、迁移、合并/恢复及回滚，明确凭据与媒体范围。
3. 后续接用户自选存储，提供自动备份、历史版本、断网恢复和保留策略。
4. 再按需要扩展多设备双向同步、冲突处理及共享实例本地账户隔离。

验收：不连接公共服务器即可导出和恢复私人数据；导入不启动副作用任务；默认备份无 Cookie、云盘密钥和媒体；异机恢复重新核验凭据与路径；损坏备份、错误密码、格式不兼容、上传中断或多设备同时备份不破坏现有数据；禁用或删除云盘连接不影响本地档案；本地清理、云端历史删除和公共跟踪相互独立。
