# 作者视频融合与按需关注设计

本文记录已实现的作者视频融合与按需关注链路。实施与验收记录见 [PLAN.md](../PLAN.md)，模块导航见 [架构说明](architecture.md)。

用户端只处理作者与视频，添加列表定义为：

```text
待添加视频 = 去重（本地已记录视频 ∪ 平台适配器可发现的视频）− 当前已关注的视频
```

当前是单管理员工作区，已关注视频就是服务器启用的跟踪目标。页面默认不勾选、不添加，允许逐项选择或“一键添加全部”。用户不需要知道适配器通过合集、投稿列表还是其他平台能力发现视频。

## 已实现链路

[source.Service](../backend/internal/source/source.go) 已通过平台注册表选择 `VideoLister`；[B站适配器](../backend/internal/provider/bilibili/list.go) 的 `GetCreatorVideos` 已封装公开合集请求，但返回不带续页信息的 `[]CreatorVideo`，且配置 Cookie 时会优先调用空间列表。目前公开合集只取目录首页及其中的预览成员，不能据此判断已发现本次能获取的全部视频。

作者资料采集已移除自动发现和关注视频；显式导入经 [tracker.IngestVideo](../backend/internal/tracker/ingest.go) 校验归属并复用 `persistVideo` 保存、记录版本和指标。添加入口和作者详情使用同一 [discovery.Service](../backend/internal/discovery/service.go)。

“全部”表示服务器本次能获取的视频范围，包含本地记录和适配器发现的并集，不保证等于作者在平台上的全部投稿。“可统计”表示可以选择加入采集，不代表列表上的视频已具有播放量等历史统计；缺失值仍显示“未采集”。

## 调用与职责

```text
+-------------------------------+
| admin                         |
| 添加 / 详情 / 选择与进度      |
+-------------------------------+
                |
                | 作者视频请求 / 添加全部
                v
+-------------------------------+     读取记录与关注状态     +-------------------------------+
| 作者视频列表用例              | -------------------------> | storage                       |
| 合并 / 去重 / 过滤 / 分页     |                            | 本地索引 / 版本 / 跟踪目标    |
+-------------------------------+                            +-------------------------------+
                |
                | platform + creator_id + 不透明续页
                v
+-------------------------------+
| source.Service                |
| 按平台注册表选择列表能力      |
+-------------------------------+
                |
                | 作者视频能力（以 B站为例）
                v
+-------------------------------+
| provider/bilibili             |
| 合集目录 / 成员 / 有限重试    |
+-------------------------------+
                |
                | 内部遍历目录与成员 / 无凭据请求
                v
+-------------------------------+
| B站公开接口                   |
| 返回可见合集与成员            |
+-------------------------------+
```

箭头表示运行时调用，结果沿原路返回。适配器向上返回扁平视频页与通用发现状态，合集只存在于 B站适配器内部；其他平台可用自己的发现方式。作者视频列表用例位于 `internal/discovery`。提交选择后转入共用的批量导入用例，沿现有查询与保存链路写入；列表查询不承担内容或关注写入。

| 层 | 负责 | 关键边界 |
|---|---|---|
| 页面与后台处理器 | 请求统一视频页、维护选择、触发添加、展示通用进度 | 不请求合集，不分别查询或合并本地与平台来源 |
| 作者视频列表用例 | 读取本地、调用平台能力、合并去重、过滤已关注、统一分页 | 不解释合集，不解析 B站 JSON，不决定平台错误是否重试 |
| `source.Service` | 按 `platform` 选择已注册的作者视频能力，透传视频页与通用错误 | 不写 B站业务分支，不定义通用合集能力 |
| `provider/bilibili` | 内部遍历全部可见合集与成员、去重并扁平化视频、分类与重试 | 不向上返回合集实体，不读写数据库，不决定管理员关注哪些视频 |
| `storage` | 本地分页与状态查询、现有内容保存和跟踪目标维护 | 不请求平台、不解释 B站业务码 |

继续使用可选的作者视频能力；其他平台无需存在合集概念。平台不支持视频发现时，仍可展示本地未关注记录与手动添加入口。

`CreatorVideoPager` 提供可续页的作者视频能力。通用契约只包含作者、视频、数量上限、不透明续页和发现状态；不增加合集接口、合集字段或合集类别。适配器游标由对应适配器解释，通用层只保存并回传；不得要求调用方自行推进 B站目录页或成员页。

哔哩哔哩适配器内部覆盖公开可见的全部目录页和各合集的成员页，处理平台返回的不同类别及重复成员，不把目录预览当作完整成员。每次能力调用只推进受预算限制的一段工作并返回视频页，后续调用继续；尚有目录或成员未完成时不能报告发现结束。部分分支失败时保留其他成功视频，返回通用的不完整状态，并由适配器保留可恢复位置。

当前哔哩哔哩发现路径必须显式使用无凭据能力；即使进程配置了现有 `BHT_BILI_COOKIE`，也不能回退空间列表或附带 Cookie。公开发现通过 [http.go](../backend/internal/provider/bilibili/http.go) 的 `getRequest(..., false)` 明确关闭凭据。这是当前 B站适配器的限制，不强制所有平台使用同一发现方式。

## 分页与状态契约

已实现接口：

| 入口 | 输入 | 输出与约束 |
|---|---|---|
| `GET /api/creators/{id}/videos`，`scope=available` | `platform`、`cursor`、受限 `limit` | 服务端融合、去重并排除已关注后的待添加视频页，统一 `next_cursor`、发现会话和加载状态 |
| 同一入口，`scope=recorded` | `platform`、`cursor`、受限 `limit` | 只读本地已记录视频，不排除已跟踪项，不请求平台；维持详情和内容库的本地读取边界 |
| `POST /api/ingest/videos` | `platform`、`creator_id`、显式视频 ID，或表示本次作者范围的“添加全部”意图 | 后台任务与进度；服务端继续枚举、校验归属、保存、加入关注，返回成功、已存在、拒绝与失败项 |
| `GET /api/ingest/jobs/{id}` | 任务 ID | 进度与逐项结果，`running` / `complete` / `partial` / `cancelled` |
| `POST /api/ingest/jobs/{id}/retry`、`/cancel` | 任务 ID | 显式重试失败及未完成项，或取消并保留成功项 |
| `POST /api/creators/{id}/videos/cancel` | `{session}` | 停止当前发现，保留已有列表和选择 |

写入接口要求 `application/json` 并检查请求来源；本期仅支持当前本地工作区的同源页面，不将此视为用户登录，也不开放未确认认证方案的外部扩展写入。单视频关注仍保留原表单入口。

页面只调用统一入口，不传入发现来源或合集 ID。服务端创建有界的发现会话，首批只等待读取本地并启动异步平台发现；本地结果附带平台仍在加载的状态，后续通过同一入口续页。发现任务使用独立、有限的生命周期和取消机制，不因首个 HTTP 响应结束而误取消，也不无限后台运行。

服务端内部记录本地位置、适配器不透明续页、本次已发现结果及已返回的视频 ID；对外只提供一个游标或发现会话，不暴露两套来源分页。会话具有容量、过期和取消约束，游标绑定平台、作者和列表范围，过期后明确提示重新加载；显式已选 ID 不因续页失效而静默丢失。

每批结果先按 `(platform, video_id)` 合并去重，再批量补齐本地状态并过滤当前已关注项。跨页继续去重；同一视频即使存在于多个合集或同时存在于本地，也只返回一次。本地详情与观测信息优先保留，不以发现时的元数据覆盖已保存的观测。去重或过滤后不足一页时，在预算内继续读取；不能按上游原始页直接过滤后宣称已到末页。

本地续页使用稳定的读取位置，不能对不断缩短的“尚未关注”结果集使用偏移量翻页；否则批量添加前面的目标后会跳过后面的目标。新增关注只影响返回前与写入前的过滤，不改写已经推进的发现位置。

列表返回 `pending`、`complete`、`partial`；平台不支持发现时以 `unsupported_operation` 提示并保留本地结果，存储或输入错误通过 HTTP 状态返回。结果页为空但发现尚未结束时，仍保留可继续推进的信息；`complete` 只表示本次可获取范围已枚举结束，不保证平台全部投稿均已覆盖。页面不显示内部合集数量、成员失败位置或平台业务码。

首屏不等待全量结果，不承诺尚未发现视频参与的全局排序，也不使用上游目录数冒充去重、过滤后的总数。常规本地内容库可搜索本地记录；可添加列表的搜索只作用于本次已发现的视频，页面明确标注范围。“一键添加全部”覆盖该作者全部待添加范围，不隐含只添加当前搜索页。

| 字段 | 当前口径 | 未来多用户口径 |
|---|---|---|
| `recorded` | `videos` 已有成功观测；作者资料是否已记录以成功资料观测为准，不能仅凭占位作者行存在 | 同左，共享历史索引 |
| `tracking` | `tracking_targets` 中目标启用 | 全局调度目标启用 |
| `subscribed` | 单管理员已关注，映射为同一目标的 `tracking` | 当前真实用户存在有效 `subscriptions` 关系 |
| `selected` | 仅前端本次添加操作的选择状态，默认 `false` | 同左，不由 `subscribed` 自动填充 |

同一条目可以同时 `recorded` 和 `tracking`，也可以只满足其中之一。停止关注后历史记录仍保留，该视频可重新出现在添加列表；新目标尚未首次采集时也可能已在跟踪，应从添加列表排除。`scope=available` 按 `subscribed` 过滤，当前就等于按全局 `tracking` 过滤；`scope=recorded` 不应用此过滤。

## 选择范围与批量导入

- 默认不勾选、不添加。已关注项由服务器过滤；未勾选不会撤销任何既有关注。翻页、失败重试和筛选切换保留显式选择。
- 逐项选择提交唯一视频 ID；“一键添加全部”提交平台、作者及本次发现范围，不要求浏览器先加载或提交所有视频，不限于当前页。按钮旁说明是添加该作者全部可获取的待添加视频。
- 添加全部由共用用例处理本次会话已经发现的全部视频，再接续尚未发现的页；已经展示但没有勾选的视频也在范围内，不能只从页面下一游标开始。按页融合、去重并过滤，分批调用现有导入链路，展示正在发现、正在校验入库、完成与部分失败的进度。通用任务不理解合集。
- 逐批重新检查关注关系，已被其他请求添加的目标幂等跳过；新发现页同样执行去重和关注过滤，不能仅过滤初始页面。重复点击应返回已有任务或复用幂等处理，不重复建立目标或写入版本。
- 统一通过 `GetVideo` 的通用作者字段校验归属后保存；平台端点与原始作者字段的解析在适配器内部。关注建立和采集保存分别反映结果，不能仅按 `recorded = true` 推断已经成功关注。
- 显式 ID、添加全部、手动粘贴与扩展提交复用同一写入用例。页面状态只是提示，提交时重新校验，不信任客户端提供的作者或元数据。
- 上游内容可能在分页期间变化，本设计不承诺平台快照一致性。只枚举本次任务的有界发现范围，不持续等待新投稿；部分失败或中断时保留成功项及未完成位置，恢复时不重复写入成功项。平台发现不完整时不能提示“全部添加完成”。
- 添加全部只产生本次视频关注，不自动关注未来新视频。添加或取消作者关注与视频关注彼此独立。

列表浏览与复选框操作不写入 `videos`、版本表或 `tracking_targets`；可使用有容量和过期限制的内存缓存。会话、去重集合、逐项结果和恢复位置保存在有容量限制的内存中，20 分钟过期；服务重启后需要重新加载，已写入的历史与关注不受影响。默认页 30、上限 100；显式选择每次最多 100 个，会话与任务各上限 64，发现上限 1000 步及约 10000 个视频。任务之间串行导入，排队也响应取消；达到限制时报告不完整，保留已完成项。

## 重试策略

<a id="retry-policy"></a>

平台请求重试由对应适配器控制，作者视频列表用例和前端不再自动叠加相同请求的重试。当前 B站策略默认每个内部请求页最多 3 次尝试，含首次；采用有上限的指数退避和抖动，整个操作另有总时限与请求预算，避免多个目录或成员页各自重试导致无界请求。

| 情况 | 处理 |
|---|---|
| 临时网络超时、连接中断 | 外层上下文仍有效时有限重试；单次请求超时与整个操作超时区分 |
| 明确可恢复的 HTTP 500、502、503、504 或已分类的临时业务错误 | 在尝试次数、总时限及请求预算内退避重试 |
| HTTP 429 或适配器识别的限流 | 按有效 `Retry-After` 等待；缺失时使用有上限的冷却时间；超出剩余预算则停止，返回可再次尝试时间 |
| 无效参数、资源不存在、能力不支持 | 直接返回，不自动重试 |
| HTTP 401、403、412，或适配器识别的登录、权限、风控限制 | 直接返回受限原因，不通过反复请求尝试解除限制 |
| JSON 或结构不符合契约、不可识别的业务错误 | 默认不重试，记录分类供排查；不能把所有业务错误都当作临时故障 |
| 成功但上游某页列表为空 | 不重试；适配器按自身分页规则判断该分支结束或继续其他分支，不把它直接当作全部视频发现结束 |
| 上下文取消、总时限或请求预算耗尽 | 立即停止，等待期间也响应取消 |
| 游标重复或页码推进后持续没有新的成员且不能确认结束 | 有界停止并标明来源不完整，不无限翻页或静默声称完整 |

上表是当前发现路径的策略，不代表上游接口有可用性保证。平台业务码的映射由适配器维护；通用层只使用结构化错误分类、是否可重试和可再次尝试时间，不解析业务码。

适配器只重试失败的内部页，不重新抓取成功页；通用用例保留已发现的视频和选择。刷新或手动重试仍遵守平台冷却时间；同平台、作者和续页的并发请求应合并或复用短期结果，适配器内部也避免重复读取同一目录或成员页。

真正完成发现且过滤后为空时提示“暂无可添加视频”；未完成或失败时提示“视频列表加载不完整，已显示当前可获取的视频，可稍后重试或手动添加”。用户端不出现合集概念。适配器内部日志可以记录合集、页、错误分类和尝试次数，通用层只处理加载状态与未完成的发现任务；不记录 Cookie 或完整上游响应。

## 单管理员工作区与未来账户

当前 [后台路由](../backend/internal/admin/server.go) 没有登录中间件，[数据库迁移](../backend/internal/storage/migrations/0001_init.sql) 也没有用户或订阅表。“管理员”是部署者和后台使用者的角色称谓。现在可以认为服务器代跟踪的目标就是该管理员的关注，服务器保存的内容由该管理员的工作区管理。

本期沿用 `tracking_targets` 表达当前关注，不提前增加用户表，不硬编码 `user_id = 1`。`videos`、`creators` 和版本表保存内容与观测历史；`tracking_targets` 保存调度目标。历史已记录不等于仍关注，取消关注不会删除历史。

排除已跟踪项只应用于添加列表，不能让视频库、已记录列表或历史详情隐藏这些内容。管理员看到的已关注就是服务器已跟踪，停止跟踪后已有记录仍能作为待添加项再次出现。

工作区管理归属不要求每条内容记录挂私人账户。平台上的 `creator_id` 表示 UP 主，与本系统未来用户身份无关；也不因管理员关注了某个作者，就推导作者名下所有视频都是管理员订阅。

未来接入真实账户时：

1. 创建实际管理员账户后，将当时启用的跟踪目标幂等迁移为该账户的订阅；不按全部历史内容生成订阅。若要恢复此前已取消关注的关系，需要另外记录或导入，不能从历史内容猜测。
2. 新建独立 `subscriptions`，按用户、平台、目标类型与目标 ID 唯一；管理员的个人关注也使用订阅表。
3. `tracking_targets` 保持按平台和目标共享，由聚合逻辑从有效订阅生成调度需求，不增加 `user_id`，避免多个用户重复查询。
4. `subscribed` 按当前用户计算，`tracking` 按全局目标计算。添加列表排除我已订阅的视频，其他用户已跟踪但我未订阅的视频仍可添加；不能将当前单管理员的全局跟踪过滤永久写死。普通用户取消自己的订阅时，其他用户仍关注的目标继续跟踪；最后一个订阅者离开时可停止，历史仍保留。
5. 若未来需要无个人订阅的系统维护目标，另行显式表达这种调度需求，不假造某个用户的订阅。

本方案只解决当前业务语义和迁移方向，不代表身份认证已实现。外部扩展的写入凭据、会话或 token 仍按 [原计划](../PLAN.md) 单独确认。

## 实施验证

| 层 | 必要验证 |
|---|---|
| 平台分发与适配器 | 无合集概念的平台正常接入；不支持发现的平台正常降级；通用结果仅为视频页；B站内部覆盖多目录页、多类别与成员后续页；不调用空间接口、不发送 Cookie；重复成员去重、空分支与不前进检测 |
| 重试 | 临时错误后成功、次数与总预算上限、429 冷却、永久错误仅尝试一次、空结果不重试、退避期间取消、部分成功保留；使用可控时钟或等待器，避免测试真实长等待 |
| 列表用例 | 服务器跨来源去重、过滤已关注、已记录但停止跟踪仍可添加、过滤后有界补页、统一游标、首批本地不等待全量发现、会话过期、空页不误报完成、已有观测优先、全部与部分失败提示 |
| 选择与导入 | 默认不勾选、一键添加全部包含已展示未勾选项与未加载页、添加导致列表缩短时不因偏移翻页漏项、并发新增关注时逐批重查、筛选切换保留选择、失败恢复、重复提交不重复入库、关注失败或发现不完整不伪报全部完成 |
| 关注关系与界面 | 页面和通用 API 无合集目录、字段或选择；作者采集不自动发现或关注视频；过滤只影响添加视图，内容库仍保留已跟踪历史；当前 `tracking = subscribed` 且 `selected` 独立 |
