# 客户端卡片库、UP 视频与详情

作者详情现采用 [数据来源与服务器回退](client-detail-data-sources.md)：Agent 优先获取平台当前资料，服务器提供历史与跟踪，平台失败再读服务器最后保存资料，版本按需加载；本地优先的卡片资料见 [本地优先资料](local-first-metadata.md)。核心功能和本机回归已完成，真实平台与VM验收见 [实施任务](../PLANs/2026-11-19-client-detail-data-sources.md)。下文的旧摘要与默认详情缓存仍适用于库、公开目录和独立视频详情；作者分支差异见对应段落。

本轮实现见 [UI 优化计划](../PLANs/2026-11-16-client-ui-content.md)，跟踪状态对账已由 [公共JSON计划](../PLANs/archive/2026-11-17-public-json-response.md) 扩展实施，详见 [协议](public-response.md)。浏览器资源内嵌在 Agent，修改后需要重新构建并启动 Agent；公开库的新增排序和 UP 投稿统计需要同步更新 backend，然后刷新资料。旧资料缺少字段时显示未知。

## 页面与卡片密度

UP 主库和视频库只保留一行标题与添加入口，不再重复展示全局页头和介绍。“本地工作空间”位于侧栏底部。库在同一会话中保留范围、查询、排序和页码。

三个目录共用 [cards.js](../client/frontend/cards.js) 和 [catalog.css](../client/frontend/catalog.css)：

| 密度 | 展示内容 |
|---|---|
| 紧凑 | 头像/小封面、名称、UID/BV、粉丝/播放基本指标、详情及管理/关注操作 |
| 标准 | 头像/封面、身份、粉丝/播放量、近7日真实观测增量、操作 |
| 宽松 | 标准信息，加发布时间；UP 增加本地已关注视频的近7日投稿数、最近投稿及播放合计 |

卡片不再显示采集状态、公共跟踪状态和内容版本数；本地提交/读取错误仍有可见提示。管理菜单支持刷新、待提交重试和取消本地关注。公开视频中已关注的目标也能直接管理。只被扫描发现、尚未记录的视频可在 B站打开，关注后才申请持续跟踪。

密度偏好存于当前浏览器 `bht.card-size`，两个库与 UP 视频区同步；Cookie 和会话密钥不写入浏览器存储。手机布局收为单列。

UP 详情视频区每页条数随密度变化：紧凑 30、标准 20、宽松 12。`GET /api/creator-videos/{id}` 和 `GET /api/follows` 的 `limit` 取 12–48，默认 20；非法值返回 400。切换密度会回到第 1 页重新请求，页码和总数按实际 limit 计算。设计见 [密度分页计划](../PLANs/2026-11-21-creator-videos-page-size.md)。

## 搜索与排序口径

库搜索和添加关注接受名称、UID/BV、标准 B站链接，包括查询参数。UID/BV 与其链接解析后使用相同标识精确查询；普通名称采用文本搜索。UP 示例 `72541187`、`https://space.bilibili.com/72541187` 和带 `spm_id_from` 的空间链接等价。视频支持 `www.bilibili.com/video/BV...`、主域名和移动域名的标准视频路径。链接只做白名单解析，不访问用户输入网址；短链解析和 B站全站文本搜索不在此范围内。

| 排序 | 口径 |
|---|---|
| 粉丝数 / 播放量 | UP 使用最新粉丝数；视频使用最新播放量 |
| UP 的播放量 | 本地已关注视频的最近缓存播放合计；只在本地库提供该排序，不代表服务器范围或账号总播放 |
| 最近热门 | 近7个 UTC 日内首末真实日采样的粉丝/播放差值，至少两个采样；未知项保留在末尾 |
| 最新更新 | 视频发布时间；本地 UP 使用本地已关注视频的最新发布时间；公共 UP 库不提供该排序 |
| 名称 | 名称排序，同值按 ID 保持稳定顺序 |
| 最近关注 | 本地关注时间，只在本地库可选 |

筛选和排序均在分页之前应用到完整结果集。新 Agent 的公开库由 [CatalogIdentity](../backend/internal/storage/catalog_identity.go) 按服务器已记录索引筛选/排序，再本地补齐当前资料；热门排序使用同类型7日历史，未知保留末尾。本地库和已获取投稿由 [library/catalog.go](../client/agent/internal/library/catalog.go) 在 Agent 内按本地完整缓存排序，不只重排当前页。服务器与当前资料发布时间为毫秒，扫描为秒，前端兼容两类历史数据。

UP 宽松卡片的投稿数、最近投稿与播放合计均由 [local_stats.go](../client/agent/internal/library/local_stats.go) 计算，范围是本地已关注且已知作者关联的视频。发布时间位于近7个 UTC 日窗口内才计入投稿数；存在未知数量或发布时间时保留未知，不把不完整汇总当成完整零值。直接复用本地摘要，不新增服务器投稿聚合或数据库迁移。

## 本地卡片资料与详情缓存

本地关注是否已提交，与是否能获取当前资料分开处理。正常 Agent 的 [current.go](../client/agent/internal/library/current.go) 先读取本地平台资料，再批量请求历史；只为本地失败或缺失字段的 ID 请求轻量兜底。页面刷新不再逐项请求目录或顺带核对任务；持续跟踪由独立后台核对负责，省略当前资料源的旧库接入方保留原路径。

本地库先显示缓存，再按当前页 ID 精确同步，最多 24 项；本地平台阶段最多 12 秒，随后一次批量历史请求。同一目标当前资料有 1 分钟缓存，同一页目标集合 60 秒内复用，翻页/筛选后的新集合独立核对；手动刷新可提前同步历史，但当前资料仍遵守缓存与风控冷却。UP 详情视频区只显示本地关注/扫描与缓存，单条刷新由 Agent 获取平台资料并在失败时回退服务器。请求按服务器代际、类型和 ID 集合合并；失败保留本地成功资料和旧缓存。

关注条目的 summary/summary_at 保存轻量资料，卡片与排序优先使用摘要，兼容旧 data.item。metadata_source/metadata_at 表达当前资料来源和时间，observed_at/growth_from/growth_to 表达服务器历史。仅默认30日、第一页、未指定快照的成功历史更新完整 data 缓存。7/90日和历史分页不能覆盖默认离线历史；选定版本不回填当前摘要。缓存写入失败仍展示成功读取的资料并提示。

所有缓存写回在锁内核对当前服务器代际和原关注身份，切服后返回的旧请求被拒绝，取消关注不被读请求重新创建。摘要写入本身不确认跟踪；浏览触发的独立Reconcile可更新pending_submission、核对时间和重试状态。关注身份使用随机follow_identity与创建时间，不能仅凭时间戳判断取关后是否同一次关注。

无资料详情通过read_code/read_error/target表达真实业务状态，有缓存时继续显示旧资料，无缓存时显示目标和关注状态，不伪造指标。HTTP200业务失败仍按ok/code识别，不能当作资料读取成功。

## UP 详情内的视频

详情路由为 `#creators/{UID}` 或 `#videos/{BV}`，公开库来源保留 `?scope=public`。UP 头像与资料位于左侧，粉丝数和真实趋势位于右侧；小屏纵向排列。视频区接在首屏之后，作者版本时间线与内容差异位于页面末尾的“查看历史版本与内容对比”中，初次不查询。资料来源与观测时间独立展示，服务器seq只表达服务器记录；平台值不写进历史曲线。

[creator-videos.js](../client/frontend/creator-videos.js) 编排两个列表：

- 已关注视频：本地私人关注中属于该 UP 的视频，包括该 UP 扫描上下文中的合作投稿。已关注但从未获取任何归属资料的旧条目暂不猜测归属，刷新或重新获取投稿后可关联。
- 未关注投稿：当前 UP 扫描中已经获取且尚未本地关注的视频；支持同样的搜索、排序、卡片密度、分页和逐条关注。

点击“获取全部视频”或“获取全部未关注视频”留在详情，显式启动原扫描任务并切换到未关注列表；支持进度、停止和继续。无 Cookie 时展示设置入口。扫描仍是全局单任务，另一 UP 正在扫描时不会在当前详情停止别人的任务；浏览页面不会自动发起平台扫描。

“全部”仍指登录态接口可枚举的可见投稿。部分、失败、取消或中断状态不称为完整；扫描标题、封面、播放量和发布时间来自平台分页。新发现投稿没有历史日采样，“最近热门”的历史增量保持未知。平台未提供播放量或封面时保留未知或占位。

关注先在本地保存，再申请服务器公共跟踪；失败保留待提交。已关注条目从未关注列表消失，已关注区即时更新；取消只影响本地。关注时将扫描来源 UP 和基本资料保存为私人 `discovery_creator_id/discovery`，扫描被其他 UP 替换或远程读取失败后仍保留关联；这些资料不会冒充服务器成功观测，也不会改写视频主作者。切页、返回和切换 UP 时使用请求代际避免旧结果覆盖当前页面。

未关注列表提供“关注本页（N）”按钮：按当前排序和当前页收集尚未本地关注的视频 ID，前端串行调用现有单条 `POST /api/follows`，后端保持一次提交一个，不新增批量接口。每项之间保留短延迟，单项失败不中断整批，全部结束后刷新列表并提示失败项；已关注项前端直接跳过。按钮处理中显示进度并禁用。批量只影响当前页，不改变扫描范围、服务器导入或排序口径。设计与验收见 [批量关注计划](../PLANs/2026-11-21-creator-videos-batch-follow.md)。

## 趋势、版本与总览

趋势可选7/30/90日或全部时间，采样日期沿用服务器 UTC 日口径，其他时间按北京时间显示。同日取最新值，只画真实点，缺失日断线，负增长保留；少于两个采样不算净变化。精确值可展开表格，`truncated` 提示服务器采样上限。

作者展开历史才按seq游标读取列表，不查询总数；选择版本只读该版，点击比较才读取上一版并复用已选快照。首次记录作为基线，计数变化不列为内容修改；上一版失败保留原快照，不伪造差异。独立视频详情保留既有版本分页和选择后比较行为。路由刷新、新标签、返回来源保持原有能力。

总览继续用 `/creators`、`/videos` 的 `total` 和完整第一页，不再截为五条；两个列表独立翻页，页长以响应为准。两个总数不是同一事务快照。总览失败保留最近缓存和时间；全局跟踪统计与近期全库版本动态仍暂缓。

## 本地接口与边界

本地新增当前资料/缓存、历史、版本和快照五个入口，共32个 API，完整清单见 [Agent 说明](../client/agent/README.md#api-接口)。

| 接口 | 本轮变化 |
|---|---|
| `POST /api/follows/refresh?kind=creator或video&id=...` | 同步最多24个当前页ID，显式ID先核对；缺省最多24项只同步摘要，受CSRF保护 |
| `GET /api/follows?kind=video&q=&sort=published&owner=123&page=1` | 链接归一化、本地全量排序和归属过滤，仍每页20条 |
| `GET /api/remote/catalog?kind=video&q=&sort=hot&owner=123&page=1` | 向8181公共目录透传排序和 UP 归属，补本地关注标记 |
| `GET /api/creator-videos/{UID}?scope=followed或discovered&q=&sort=published&page=1` | 只读组合 `catalog/job/configured/busy_elsewhere`，不启动扫描 |
| `POST /api/scan`、取消、继续 | 复用原有扫描路径；详情不跳转 |
| `POST /api/follows` | 若视频来自当前扫描，同时保留私人投稿来源上下文 |

作者详情改用独立 `/api/current/creator/{id}` 与 `/api/history/creator/{id}`；缓存入口无网络，平台失败才调用服务器 `/saved`。当前资料和历史分开缓存，旧默认详情只兼容回退30日历史。视频及旧调用保留 `GET /api/library/{kind}/{id}?days=7|30|90|all&page=1&seq=...` 的既有范围限制；切换范围失败保留上次成功数据。

会话、Host/Origin、写入 CSRF、固定远程路径、拒绝重定向和 Cookie 不转发约束保留。作者当前图片直接使用平台/保存资料的白名单URL；作者视频区无URL时保留占位，不间接请求旧完整详情。其他旧入口保留原快照图片解析。Windows 静态资源层返回所有 `.js/.mjs` 的JavaScript MIME，新增模块也内嵌并回归，避免nosniff阻断界面。

## 观看历史

[history.js](../client/frontend/history.js) 负责历史页交互，[HTTP 接口](../client/agent/internal/httpapi/history.go) 组合本地历史与关注状态，[扫描服务](../client/agent/internal/scanner/history.go) 拉取平台游标并将历史保存到本机 `history.json`。历史不上传公共服务器，浏览列表不会自动关注目标。

- 首次进入历史页，在 Agent 会话和配置读取就绪后并行读取本地缓存、同步最近 30 天；无 Cookie 时仍展示缓存，并提供设置入口。Cookie 从未配置变为已配置时，可自动开始同步。
- 当前页面会话内，自动同步尝试间隔至少 5 分钟，仅在进入页面时检查；没有后台定时拉取。切换视频 / UP 主、3 / 7 / 30 天范围或翻页只读取本地历史，缺失的 UP 头像另按可见区域补取；手动「同步历史」可随时更新，进行中的同步不会重复提交。
- 同步与本地列表读取分别管理状态；同步不锁定筛选和卡片，较晚返回的旧页不会覆盖新选择。同步完成保留当前范围、类型和页码；失败保留缓存、显示原因，可手动重试。历史同步使用 100 秒客户端等待预算，与 Agent 的 95 秒写入预算相容，避免沿用普通读取的 25 秒超时。
- 视频封面、UP 头像、标题与卡片空白处进入已有站内详情；视频卡片的作者链接进入 UP 详情。「B站播放 / B站主页」是独立新标签链接，关注按钮不触发导航。原生链接保留键盘访问与修饰键行为。
- 图片复用 [images.js](../client/frontend/images.js) 的 HTTPS 归一化、CDN 白名单、懒加载和加载失败占位。优先使用历史封面或已有本地头像；UP 缺少可用地址时，通过 `GET /api/images/creator/{id}?seq=0` 按可见区域补取当前头像，最多并发 4 个元数据请求，复用图片缓存、请求合并和失败退避。补取只读取资料，不自动关注；失败保留首字占位。视频缺少封面时仍保留占位，不额外请求视频详情。图片不用受 CSP 阻止的内联样式。
- 历史分页响应增加 `followed`，UP 分页可附带缓存 `cover`；字段由 `library.CurrentCache` 只读补齐，不写历史或请求网络。已关注项禁用重复关注；本次关注显示「关注中」「已关注」或「已关注 · 待提交」，待提交不等于服务器确认。重新进入页面以本地状态为准。
- 「仅看未关注」适用于视频和 UP 主，可与观看范围、卡片大小组合。两个分页接口支持 `unfollowed=1`，省略或 `0` 显示全部，其他值返回 400。未关注按本地关注判定，已本地关注但待服务器确认的目标也排除；视频按 BVID、UP 按作者 ID 筛选，在计算 `total` 和分页前完成，UP 的观看视频数保留原聚合口径。筛选结果中关注成功会重新读取当前页，补齐列表、更新总数；末页消失时回退至仍有结果的最后一页。
- 「卡片大小」共用 [view.mjs](../client/frontend/view.mjs) 的 `cardPageLimits`、库页面的 `bht.card-size` 偏好及 `bht-density` 事件：紧凑每页 30 项、标准 20 项、宽松 12 项。两处设置同步，历史中的视频和 UP 都按密度调整布局、图片和信息字号；切换筛选或大小回到第一页，仅请求本地接口。页脚展示筛选后总数、页数及每页数量，移动端工具栏分两列。

历史页使用独立卡片样式，始终展示观看时间；UP 列表展示观看视频数。活动页签会更新 `aria-pressed`，列表读取、同步、空记录和 Cookie 失效都有对应反馈。完整功能计划仍见 [观看历史计划](../PLANs/2026-11-21-watch-history.md)，其中更广的记录状态分类、批量操作与同步恢复不在本次 UI 优化范围。
