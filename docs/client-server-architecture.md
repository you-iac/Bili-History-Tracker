# 服务器跟踪与本地 Agent 协作设计

状态：目标设计，待实施。本次只更新设计和文档。当前 Agent 仍只提供本地 Cookie 验证、UP 投稿 ID 扫描和导出，见 [现有实现](client-discovery.md)。服务器 8182 已能读取历史、管理跟踪和批量导入；Agent 接入远程查询与采集申请、本地关注库和视频下载尚未实现，评论和弹幕留待后续。

目标改为多人共用公共数据池：公共跟踪服务器不建设用户注册登录，不保存“谁关注了谁”；每个人在自己的 Agent 管理私人档案、关注、平台 Cookie、任务与文件，未来可自行选择个人云盘备份。服务访问凭据和管理员身份不属于个人关注账户。

## 职责

| 部分 | 做什么 | 保存什么 |
|---|---|---|
| 远程服务器 | 提供公共 UP/视频资料、版本与指标历史；接纳采集目标，去重后持续跟踪 | 公共目标、采集状态、历史及必要的服务访问控制记录 |
| 本地 Agent | 管理个人关注、查询公共历史、按需搜索发现、申请公共采集、执行下载 | 本地关注、配置、受保护凭据、缓存、申请/扫描/下载进度及文件 |
| 浏览器界面 | 关注 UP 库、视频库、发现、下载任务和设置 | 经本地 API 操作 Agent，不把个人关注清单同步到服务器 |

服务器的“跟踪”是公共采集任务，本地的“关注”是个人列表，两者独立。Agent 不定时采集自己的粉丝、播放量或资料历史，但可持久化本地关注、缓存和任务检查点。

```text
+--------------------------------------+
| browser: favorites / discovery       |
+--------------------------------------+
                   | local HTTP
                   v
+--------------------------------------+
| Agent: private favorites / downloads |
+--------------------------------------+
                   | HTTPS: lookup / request tracking
                   v
+--------------------------------------+
| server: shared targets / history     |
+--------------------------------------+

+--------------------------------------+
| Agent: discovery / download          |
+--------------------------------------+
                   | HTTPS + local platform Cookie
                   v
+--------------------------------------+
| video platform: current data / media |
+--------------------------------------+
```

箭头表示运行请求，结果原路返回。个人关注与文件留在 Agent；查询和采集申请仍会把目标标识发给服务器。服务器可能观察到请求来源、时间和访问凭据，这个设计不等于匿名访问，也不承诺双方完全无关联。

## 页面

参考 8182 的布局和指标口径，但客户端关注库由本地关注列表决定，不能直接把 8182 的全局跟踪列表当作“我的关注”。

| 页面 | 数据与操作 |
|---|---|
| 关注 UP 库 | 本地关注的 UP 标识，合并服务器资料、版本、粉丝趋势和增减；可取消本地关注、获取全部可见视频，再选择关注视频 |
| 关注视频库 | 本地关注的视频标识，合并服务器播放量与版本；可取消本地关注和创建本地下载 |
| 搜索发现 | 分开搜索服务器公共记录与平台当前候选；支持 UID/BV/链接查找，按平台能力扩展关键词搜索；显式关注或下载 |
| 下载任务 | 本地排队、执行、暂停、失败、完成和文件信息 |
| 连接与本地设置 | 服务器地址、可选服务访问凭据、平台 Cookie、下载目录与本地档案 |
| 数据管理（规划） | 管理档案、占用、导入导出、备份恢复及清理；未来配置个人云盘、自动备份和历史版本恢复 |

关注 UP 不自动关注其全部历史视频；候选默认不选，支持跨页选择。浏览、发现或下载不自动创建关注。个人关注增删立即以本地保存结果为准，服务器是否在采集单独显示。

## 关注与发现流程

1. 用户点击关注，Agent 先保存本地关注项。
2. Agent 查询公共目标状态；已在跟踪则复用，不要求服务器再采集一次。
3. 尚未跟踪时，Agent 提交平台、类型和目标标识，申请服务器跟踪，不上传完整关注列表、平台 Cookie 或私有响应。
4. 服务器去重、检查策略并验证公共可采集性，按下表返回结果；Agent 单独显示“已本地关注”与“服务器待处理/跟踪中/拒绝”。
5. 超时先查公共状态或申请结果，再幂等重试；服务器拒绝或暂时不可用不删除本地关注。
6. 本地取消关注只删除本地列表项，保留缓存、下载及服务器公共任务。普通客户端没有全局停采和删除历史权限。

UP 详情的“获取全部视频”复用现有 Cookie 分页扫描，全部仅指当前登录态下可枚举范围。合作投稿保留在候选中，服务器记录真实视频作者，不把来源 UP 强行写成原作者。

## 服务器接纳与去重

区分“已有数据”和“正在跟踪”，不能只查询记录是否存在。

| 状态 | 服务器处理 |
|---|---|
| 已有且正在跟踪 | 返回公共状态，复用目标；不因每次申请立即刷新或修改采集间隔 |
| 已有记录但未跟踪 | 按管理员策略允许恢复或拒绝；不能绕过暂停/拒绝名单 |
| 未有记录 | 合并并发申请，调用可信公开查询；成功后保存资料并加入跟踪，失败不伪造有效数据 |
| 仍在处理 | 返回待处理状态；接受入队不等于已验证或已跟踪 |
| 无效、不可公开获取或超额 | 返回明确失败或等待原因，本地关注可保留 |

目标唯一键为 `(platform, kind, id)`；并发申请在请求和最终写入两层去重，不能每个调用都创建采集任务。查看公共记录不隐式申请跟踪，申请接口不信任客户端提供的标题、计数或原始元数据。

服务器不知道所有人的私人关注关系，因此不能自动判断“最后一个用户已取消”。默认公共跟踪不随本地取消而停；保留、降频、暂停与清理由管理员的预算和服务策略统一控制。若未来必须按最后一个订阅者取消而停采，就需要增加服务端订阅或租约状态，届时再评估身份体系。

## 历史与当前值

- 服务器是公共资料、版本、粉丝与播放量历史的权威来源；个人关注列表以本地为准。
- 指标增减为所选观测区间末值减首值，保留负数；少于两个样本显示未知，不补造历史。
- 元数据版本和指标样本分开，计数变化不直接当作新内容版本。
- 本地查询结果标记平台来源，服务器缓存标记观测与缓存时间，不混写为新历史。
- 历史版本是元数据记录，不意味着保存了相应历史媒体，只能下载当前仍可访问的内容。

## API 分层

### 已有本地 API

现有 10 个接口仍只提供本地会话、Cookie 和扫描，见 [Agent API 清单](../client/agent/README.md#api-接口)。远程能力按下表复用 8182；后面的本地扩展路由仍为草案。

### 复用 8182 远程能力

Agent 连接现有服务器 8182 的同一套数据能力，不另建查询服务，不预设另一套 `/api/v1/public/...` 或 `/api/v1/target-requests` 路由。已有 JSON 接口直接使用；缺少 JSON 的页面优先在原路径支持 `Accept: application/json`，默认 HTML 行为保留。下表的补齐项均尚未实现。

| 能力 | 当前路由与实现 | Agent 接入需要补齐 |
|---|---|---|
| UP / 视频库 | `GET /creators`、`GET /videos`，目前返回 HTML | 共用 `Catalog` 补 JSON 分页及有界按 ID 查询，供本地关注列表合并资料 |
| 详情与版本 | `GET /detail/{type}/{id}`，目前返回 HTML，支持版本选择与列表分页 | 共用 `Content`、`Versions`、`ReadSnapshot` 补结构化 JSON，不解析页面 HTML |
| 粉丝 / 播放指标 | `GET /api/metrics/{type}/{id}?days=30` 已返回 JSON | 直接复用现有指标口径与时间范围 |
| 公共跟踪状态 | `GET /api/targets/status` 已返回当前跟踪列表的分页状态，主要供页面展示 | 补按目标标识查询、明确已记录/未跟踪/处理中等状态，不能把某页未出现当成不存在 |
| 单个目标提交 | `POST /targets` 已接受 `type`、`id` 表单，添加后异步采集，可按 `Accept` 返回 JSON | 复用新增与调度链路；公共重复申请不能沿用立即刷新和改间隔行为，不能让未验证目标被报为采集成功 |
| 批量视频提交 | `POST /api/ingest/videos` 已接受 JSON，需 `creator_id` 和 `videos`，显式列表每次最多 100 个 | 复用既有校验入库任务；按真实作者组织视频，保留准入、去重与管理员暂停策略，不将现有协议描述成只需 BV 列表 |
| 导入结果 | `GET /api/ingest/jobs/{id}` 已返回逐项结果 | 直接复用结果，补公共目标状态对账；现有内存任务不能视为永久申请记录 |
| 管理停采与保留 | 8182 已有管理命令 | 保留管理员权限，普通 Agent 只查询和申请采集 |

管理网页由服务器调用 `Catalog / Content / Metrics / Versions` 读取 SQLite 后渲染；Agent 经 HTTP 获取相同查询结果。复用的是数据与业务逻辑，远程 Agent 不直接调用服务器 Go 对象或打开数据库。已有 JSON 可在部署可达时由 Agent 调用，当前尚缺普通客户端准入和完整数据输出。

普通客户端不上传或读取个人订阅关系，也不使用管理停采命令。8182 可以同时承载管理网页和供 Agent 使用的数据接口；按路由区分权限，不要求另起服务或端口，不把整个管理后台作为普通客户端权限开放。

### 待新增本地 API

| 能力 | 路由草案 | 处理方式 |
|---|---|---|
| 连接设置 | `/api/remote/connection` | 保存公共服务器地址及可选访问凭据，只返回摘要 |
| 个人关注增删 | `/api/follows/{kind}/{id}` | 写本地列表；添加后可查询或申请公共采集，删除不停止公共目标 |
| UP / 视频关注库 | `/api/library/creators`、`/api/library/videos` | 从本地列表分页，按当前页标识查询公共数据并合并 |
| 详情和历史 | 本地库的详情、版本、指标接口 | 读取公共数据与本地缓存，不新增自己的长期平台采集 |
| 按需发现 | 保留 `/api/scan`，扩展平台查找 | 用户显式发起，使用本地 Cookie |
| 下载任务 | `/api/downloads` 及暂停/继续/取消 | 文件和任务状态留本地，直接请求平台 |
| 本地数据管理 | 档案、备份和存储连接 API，具体路由待定义 | Agent 本地管理与恢复，未来直接访问用户自选存储，不交给公共服务器 |

本地 API 继续验证会话、Host/Origin 和 CSRF，不提供任意 URL、路径或命令代理。

## 视频下载与后续文件

近期目标为手动视频下载：从个人视频库或发现结果选择视频，设置本地目录、可获取清晰度和分 P，保存进度并支持暂停、继续、失败重试和重启恢复。上游支持时才续传，临时媒体地址过期时重新解析；音视频合并需明确本地工具依赖，未完整文件不能标完成。

媒体直接从平台保存本地；服务器无需知道是否下载、保存到哪里或文件内容。视频下载与关注独立，不自动向服务器提交目标；只有明确的公共采集申请才触发服务端接纳。

评论和弹幕是后续独立本地文件任务，分别启用并关联视频/分 P，保存范围、检查点和部分结果。视频完成不代表其他文件已保存。

## 登录与必要状态

多人使用公共数据池不必然需要服务器账号。当前目标是每个人运行自己的 Agent 和独立数据目录，服务器不保存用户名密码、个人关注、下载记录或私有工作区。

| 边界 | 方案 |
|---|---|
| 浏览器 → Agent | 保留本地会话保护；一人一实例时无需额外账号密码 |
| Agent → 公共服务器 | 查询按公开策略访问；采集申请使用服务限额、可选安装凭据或其他准入措施，不绑定私人关注账户 |
| Agent → B站 | Cookie 在本地保护保存，只用于当前平台能力 |
| Agent → 用户自选云盘（未来） | 使用用户配置的存储认证，直接传输所选加密备份，不经公共跟踪服务器 |
| 服务器管理端 | 管理员保有全局控制权，与普通服务使用者分开 |

不要求先做完整本地账户系统。一个操作系统用户用一个档案即可；同一台机器可使用独立系统账户、Agent 端口和数据目录。若一个 Agent 实例服务多个人，才需要真正的本地登录与存储隔离；仅增加一个“档案切换”按钮不构成安全隔离。当前程序仍只有单份配置/任务状态，不能宣称已实现共享实例的多用户隔离。

Agent 有本地状态：关注列表、配置、Cookie、缓存、待确认申请、下载进度和文件索引。用户资料和偏好可组成自主管理、备份与迁移的本地档案，不必由项目服务器托管身份。服务器没有个人关注状态，但仍保存公共跟踪、历史、队列和必要访问控制状态；因此更准确的名称是“公共数据服务 + 本地私人客户端”，并非两端完全无状态。

先提供本地数据概览、导入导出、备份恢复和分类清理，未来 Agent 自动备份到用户自选云盘。公共服务器不接收私人档案，也不承担云盘授权或密钥找回；默认排除敏感凭据和媒体，用户可单独选择加密凭据或媒体备份。首期云盘能力是版本化备份与按需恢复，多设备双向同步另行设计，详见 [本地数据管理](client-data-management.md)。

## 服务访问控制与成本

无用户账号不代表无限制接受新增跟踪。公共查询和新增采集分开限流；限制请求大小、批次数、并发和总目标数量，使用有界队列、冷却、拒绝名单及管理员暂停开关。已有目标重复申请应复用结果，不能反复触发即时采集。

部署可给受控安装发放可撤销的服务访问凭据，以区分读与申请权限和预算，不建设用户资料或订阅表；面向公众的匿名入口也必须有独立准入及全局预算策略。凭据不内置成一个可提取的共享管理员密钥，不允许客户端自称管理员。远程使用 HTTPS，敏感访问凭据放请求头。

必要运维日志和凭据记录不等于私人关注关系；目标查询和提交仍可能暴露访问元数据，不能承诺匿名。可参考 [OWASP REST 安全](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html) 与 [API 资源消耗控制](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/)。

通过本地导入导出和用户自选云盘迁移私人关注，不要求公共服务器建立账户。只有项目自身将来提供私人数据托管、账号找回、按用户计费或服务端个人通知时，才再评估中心化身份与存储。个人云盘认证和备份密钥由用户管理，公共服务器不代为恢复。

## 实施顺序与验收

1. Agent 优先复用 8182 现有 JSON 与导入流程；列表、详情和版本补 JSON，状态补按 ID 查询，提交补公共准入与幂等边界，共用既有查询和调度。
2. Agent 增加独立本地关注存储与两个个人库，远程响应按标识合并；添加关注与公共跟踪申请分状态显示，取消仅影响本地。
3. 加入按需发现、申请队列对账和本地视频下载、文件验证及恢复。
4. 实现本地档案、数据管理与备份恢复；后续扩展评论、弹幕和用户自选云盘自动备份，再评估双向同步。个人云盘不以公共服务器账户为前置条件。

验收重点：两个 Agent 的个人关注互不影响；相同目标只有一套公共跟踪；已有目标不被重复即时刷新；有记录未跟踪不误判；未知目标经验证后入库，失败不伪造成功；本地取消不全局停采；本地关闭后服务器继续采集；私人数据不上传公共服务器，个人云盘只备份用户所选范围；公共写入有资源边界；现有 10 个本地接口保持当前能力，规划不冒充已实现。
