# 服务器跟踪与本地 Agent 协作设计

状态：目标设计，待实施。当前代码只完成本地 Cookie 验证、UP 主投稿 ID 扫描和导出，见 [现有实现](client-discovery.md)。本文定义下一步的远程记录浏览、关注管理和本地视频下载；评论与弹幕文件留待后续。

## 职责

| 部分 | 做什么 | 保存什么 |
|---|---|---|
| 远程服务器 | 持续跟踪 UP 和视频，记录资料版本、粉丝与播放量变化；管理关注、设备及权限 | 历史、指标样本、关注关系、采集任务和设备记录 |
| 本地 Agent | 查询远程记录、按需搜索发现、提交关注操作、执行本地下载 | 配置、受保护凭据、可清理缓存、待确认操作和下载进度 |
| 浏览器界面 | 关注 UP 库、视频库、搜索发现、下载任务和设置 | 展示状态；通过本地 API 操作 Agent |

长期采集只在服务器执行。Agent 不定时请求平台来维护粉丝、播放量或内容版本历史；按需扫描和下载的检查点属于本地任务状态，可以保存。

```text
+--------------------------------------+
| browser: libraries / discovery       |
+--------------------------------------+
                   | local HTTP
                   v
+--------------------------------------+
| Agent: remote client / local tasks   |
+--------------------------------------+
                   | HTTPS: history / follows
                   v
+--------------------------------------+
| server: tracking / history / access  |
+--------------------------------------+

+--------------------------------------+
| Agent: discovery / download          |
+--------------------------------------+
                   | HTTPS + local platform Cookie
                   v
+--------------------------------------+
| video platform: current data / media |
+--------------------------------------+
```

箭头表示运行时请求，结果原路返回。关注和历史数据经服务器，搜索发现和媒体文件经平台；平台 Cookie、媒体文件、本地路径不发给项目服务器。

## 页面

参考 8182 的交互和业务口径，新增客户端页面，不抓取或嵌入远程管理页。

| 页面 | 数据与操作 |
|---|---|
| 关注 UP 库 | 从服务器读取当前工作区关注的 UP；看资料、资料版本、粉丝趋势与增减；关注或取消关注；按需获取该 UP 全部可见视频，再选择提交视频关注 |
| 关注视频库 | 从服务器读取关注视频；看播放量、趋势和内容版本；关注或取消关注；选择当前可获取的视频下载到本机 |
| 搜索与发现 | 区分“服务器已记录内容搜索”和“平台当前发现”；支持 UID/BV/链接查找，并按平台能力扩展关键词搜索；选中后显式关注或下载 |
| 下载任务 | 查看排队、下载、暂停、失败和完成；暂停、继续、取消、定位本地文件 |
| 连接与账号 | 服务器地址、设备连接状态、B站 Cookie、下载目录和并发设置 |

UP 关注和视频关注分别管理。关注 UP 先跟踪其资料及粉丝，不自动关注历史全部视频；获取视频列表是按需发现，选择一个、多个或跨页全部关注才提交给服务器。浏览、发现或下载本身不自动关注。

本地显示的关注状态以服务器确认为准。请求尚未确认时显示“待提交/待确认”；失败或断连不能显示已关注。取消关注不删除历史或本地文件。多人模式只移除当前用户的关注，共享目标是否继续采集由服务器统一决定。

## 历史与当前值

- UP 的资料、版本、粉丝样本以及视频的元数据、版本、播放量样本来自服务器；注明真实观测时间。
- 选定时间范围内的增减为最后样本减最早样本，保留负数。少于两个样本时显示未知，不用当前值补造过去趋势。
- 内容版本记录资料或元数据变化，指标样本记录粉丝或播放量变化；统计变化不等于产生新的内容版本。
- 本地搜索发现的数据注明“本次平台查询”，不覆盖服务器历史，也不把本地缓存标成新采集结果。
- 服务器保存的历史版本是元数据历史，不代表保存了对应版本的媒体文件；本地下载只能获取平台当前仍可访问的媒体。

## 关注与发现流程

1. Agent 读取远程的关注 UP 库和视频库，详情按需请求历史、指标和版本。
2. 用户在 UP 详情点击“获取全部视频”，复用现有本地 Cookie 分页扫描。全部仅指当前登录态下可枚举的范围。
3. 候选默认不选。逐项、批量或跨页选择后，Agent 向远程服务器提交视频标识及必要的幂等信息。
4. 服务器鉴权、查询校验并持久化关注及跟踪目标，返回逐项结果；客户端再更新关注状态。
5. 超时先查询实际状态，按操作标识对账；待确认操作可本地保存，不能变成另一套关注事实。

投稿列表可包含合作视频，不能因主作者不同就丢弃。视频关注以视频标识提交，服务器保存真实作者；来源 UP 不强行改写视频作者。批量流程复用现有校验，但要审查原有“指定作者归属”限制与合作投稿的差异。

Agent 不运行本地“持续跟踪新投稿”规则。若后续提供此类自动规则，应放在服务器可采集能力内，不能要求服务器使用用户本地 Cookie，也不能承诺发现平台未向服务器开放的投稿。

## API 分层

### 已有本地 API

现有 10 个 API 继续提供会话、Cookie 与扫描能力，见 [Agent API 清单](../client/agent/README.md#api-接口)。它们尚未具备远程访问和下载能力。

### 待新增远程 API

以下是能力草案，路由和字段在实施时确定；不能将它们视为可调用的现有接口。

| 能力 | 路由草案 | 关键约束 |
|---|---|---|
| 设备与工作区 | `GET /api/v1/client/device` | 返回工作区、设备和允许的操作；支持撤销设备 |
| UP / 视频库 | `GET /api/v1/client/creators`、`GET /api/v1/client/videos` | 支持当前工作区关注过滤、搜索和稳定分页 |
| 详情、版本与指标 | 各对象下的详情、`versions`、`metrics` | 读取服务器数据库，返回观测区间和版本标识，不因打开页面就请求平台 |
| 关注管理 | `PUT/DELETE /api/v1/client/follows/{kind}/{id}` | 幂等增删；服务器校验并持久化；返回已确认的状态 |
| 批量关注与对账 | 批量申请及申请状态查询 | 限制单批数量，逐项确认，超时可以查询，不假报全部成功 |

远程 API 与 8182 复用业务和存储能力，补独立的鉴权、权限检查及 JSON 协议；不把未鉴权的管理页直接开放给客户端。服务器继续独立运行采集任务。

### 待新增本地 API

| 能力 | 路由草案 | 处理方式 |
|---|---|---|
| 远程连接 | `/api/remote/connection` | 保存地址和受保护设备凭据；查询只返回摘要 |
| 两个关注库 | `/api/library/creators`、`/api/library/videos` | 调用远程 API，按工作区隔离缓存 |
| 详情、版本与指标 | 库对象的详情、版本与指标接口 | 转换远程响应，不在 Agent 采集历史 |
| 关注操作 | `/api/follows/{kind}/{id}` | 调用服务器并保存待确认操作，不直接宣布成功 |
| 按需发现 | 保留 `/api/scan`，扩展平台查找接口 | 用户显式发起，使用本地 Cookie |
| 下载任务 | `/api/downloads` 及任务暂停/继续/取消 | Agent 直接连接平台，文件和进度留在本机 |

本地层继续验证会话、Host/Origin 和 CSRF。远程调用限制在明确协议内，不提供任意 URL 或命令代理。

## 视频下载与后续文件

近期交付目标包含手动视频下载：从视频库或发现结果选择视频，设置本地目录及可获取的清晰度、分 P 范围，创建持久化任务，展示进度并支持停止、失败重试和重启恢复。上游支持续传时才续传；媒体地址过期时重新解析。需要音视频合并时明确本地工具依赖，不能把只有画面或只有声音的文件标成完整视频。

下载文件直接从平台到本地，不经项目服务器。记录 BV、分 P 标识、清晰度、路径、大小和可用校验信息，完成前验证文件；临时或失败文件不标完成。目录由本地用户设置，服务器不能下发任意路径或系统命令。是否被服务器关注不是下载的必要条件。

评论和弹幕是后续独立文件任务，分别启用和保存，沿用视频/分 P 关联、分页或分段进度、部分结果标识和本地导出。视频下载成功不等于评论或弹幕也已保存。

## 登录与必要状态

建议 Agent 不另建用户名密码和账户数据库。是否需要身份认证、是否保存状态分别决策：远程接口需要识别设备和工作区，本地也需要保存配置与任务。

| 边界 | 建议 |
|---|---|
| 浏览器 → Agent | 保留已有本地会话保护，无需每次输入一套本地账号密码 |
| Agent → 远程服务器 | 个人先绑定单一工作区，每台设备使用可撤销、可轮换且限制权限的凭据；多人使用时在服务器登录账号、按用户/工作区发放设备凭据 |
| Agent → B站 | 本地 Cookie 是平台登录态，与服务器账号和设备凭据分别管理 |

服务器凭据在 Agent 中受保护保存，放入 HTTPS 请求头，不放查询串或网页存储。服务器按每次请求检查设备、工作区和读写权限；设备撤销后不能继续访问。多人场景不能仅靠一个共享管理员密钥隔离用户数据。建议参照 [OWASP REST 安全指导](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html) 实现传输和对象级访问控制。

| 状态 | 保存位置 |
|---|---|
| 关注关系、长期采集任务、版本和指标历史 | 服务器为唯一权威来源 |
| 服务器配置、设备凭据、平台 Cookie | Agent 配置与系统保护存储 |
| 服务器响应缓存、关注显示缓存 | 本地可清理缓存，按服务器实例和工作区隔离 |
| 扫描进度、关注操作待确认队列、下载进度和文件索引 | 本地持久化任务状态 |

因此建议“没有独立本地账户体系、保留必要状态的 Agent”，而不是要求退出就丢失全部配置和任务。远程账号失效只影响远程访问，本地 Cookie 失效只影响平台能力；退出平台登录不会取消服务器跟踪。

## 实施顺序与验收

1. 补服务器设备认证、库/详情/指标/版本读取及关注写入 API；先复用现有单工作区，协议保留未来用户归属。
2. Agent 增加远程客户端，界面提供关注 UP 库、视频库和按需搜索发现；用服务器确认结果维护关注显示。
3. 增加本地手动视频下载、文件校验、任务与恢复。本轮目标到视频下载，评论和弹幕不作为当前已交付能力。
4. 后续再加评论/弹幕文件、多人账户和更完善的事件同步。近期先按需查询服务器记录，不强制先构建完整事件复制系统。

必要验收：Agent 关闭后服务器继续采集；Agent 不写自己的长期指标历史；两个库反映服务器关注状态；批量关注和超时重试不重复创建目标；负增长、缺失样本和版本变化正确显示；下载不经服务器、关闭网页后继续、重启可恢复；设备撤销阻止远程读写；平台 Cookie、媒体、评论、弹幕及本地路径不上传服务器。
