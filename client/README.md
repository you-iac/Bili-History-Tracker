# 客户端需求与设计

状态：已实现首个独立功能：本地 Cookie 配置与账号验证、指定 UP 主的可见投稿视频 ID 全量分页扫描、结果查看及 TXT/JSON 导出。公共记录浏览、本地关注管理、采集申请、视频下载、评论与弹幕仍待实施。本文统一定义界面与 Agent 的需求及验收；除“当前实现与启动”外，后续章节保留整体规划，不能视为均已实现。平台级产品需求见 [PRD](../docs/PRD.md)，实施记录见 [PLAN](../PLAN.md)，模块导航见 [架构说明](../docs/architecture.md#module-navigation)。

## 当前实现与启动

需要 Go 1.26 或更高版本。在仓库根目录执行：

```powershell
cd client
go run ./agent/cmd/agent
```

打开终端输出的完整本地链接（默认 `127.0.0.1:8183`，包含本次启动的连接密钥）。粘贴已登录 B站请求的 Cookie 并验证，输入 UP 主 UID 或 `https://space.bilibili.com/{UID}`，开始扫描。输出视频标识为 BV 号；页面展示真实进度和部分结果，支持跨页查看、复制全部 ID、TXT/JSON 导出，以及停止和继续。仅保留最近一次扫描，重新扫描会替换当前任务。

浏览器界面已通过 `go:embed` 内嵌，无需启动前端开发服务或安装 Node 依赖。构建独立程序：

```powershell
go build -o bin/agent.exe ./agent/cmd/agent
.\bin\agent.exe
```

可通过 `-listen 127.0.0.1:8183` 和 `-data data` 指定端口及本地目录，禁止监听非回环地址。Windows Cookie 使用当前用户的 DPAPI 加密保存到 `data/cookie.protected`；其他平台暂只在进程内保留 Cookie，退出后需重新导入。扫描结果与续页位置逐页保存到 `data/scan.json`；刷新或关闭网页不会取消任务，重启 Agent 后可继续未完成任务。

本期采用手动导入 Cookie；普通网页不能直接读取 B站域名的登录 Cookie，自动读取需浏览器扩展及授权，留待后续。平台限流、风控、账号失效、分页停滞或数量变化时保留结果并标记不完整；“全部”仅指这次登录态下投稿接口可枚举的范围。实现、API、验证与具体边界见 [客户端发现技术说明](../docs/client-discovery.md)。

## 产品目标与职责

多人各自运行 Agent，共用服务器公共资料和历史。个人关注、Cookie、配置、下载任务及文件保存在本地；服务器只管理公共采集目标，不保存“谁关注了谁”，不要求用户注册登录。

| 部分 | 职责 |
|---|---|
| 远程服务器 | 公共 UP/视频资料、版本与指标历史；校验并去重采集申请，持续跟踪公共目标 |
| 本地 Agent | 私人关注库、公共数据查询、按需搜索发现、公共采集申请、本地视频下载 |
| 浏览器界面 | 个人关注 UP 库、视频库、搜索发现、下载任务与本地设置 |
| 本地平台适配器 | 使用本地 Cookie 验证账号、读取当前可见投稿和媒体 |

长期历史由服务器维护，Agent 不周期采集自己的指标历史。Agent 可以保存关注与任务检查点；这属于有本地状态的客户端，不是退出就丢失配置的无状态网页。

## 运行方式与协作关系

浏览器通过同源 API 访问本地 Agent。Agent 查询服务器公共资料/历史，必要时向受控入口申请采集目标；另用本地 Cookie 向平台按需发现和下载。

远程接入优先复用现有 8182：指标、跟踪状态与导入已有 JSON；列表、详情和版本共用管理页的数据库查询，补 JSON 输出即可。不另建查询服务，Agent 不解析管理页 HTML，也不直接访问服务器数据库，见 [具体复用范围](../docs/client-server-architecture.md#复用-8182-远程能力)。

```text
+--------------------------------------+
| browser: private libraries           |
+--------------------------------------+
                   | local HTTP
                   v
+--------------------------------------+
| Agent: favorites / local tasks       |
+--------------------------------------+
                   | HTTPS: lookup / target request
                   v
+--------------------------------------+
| server: public targets / history     |
+--------------------------------------+
```

个人关注列表不上传为云端订阅，下载文件直接从平台到本机。查询和申请仍向服务器发送目标标识，访问日志可能包含来源与时间，不能把这种分工理解为匿名或完全没有关联。8182 继续作为管理员管理页，普通客户端不使用它的全局停采权限。

## 身份、数据与状态

当前目标不建设服务器用户账号，也不强制完整本地账户系统。每个人优先使用独立 Agent 与数据目录；共用一个实例时，再增加真正的本地身份与存储隔离。当前代码的单份 Cookie/任务配置还不能作为共享实例的多用户隔离。

- 浏览器访问 Agent：保留现有本地会话、Host/Origin 和 CSRF 保护。
- Agent 访问公共服务器：按部署策略查询；新增采集受准入、限额和可选服务访问凭据控制，不绑定个人关注账户。
- Agent 访问平台：本地 Cookie 单独管理，只发往对应平台。

| 数据 | 权威位置 |
|---|---|
| 个人关注、偏好、本地档案 | 本地 Agent |
| 公共目标、资料版本、粉丝与播放量历史 | 服务器 |
| Cookie、配置、扫描/下载进度、文件 | 本地 Agent |
| 服务器响应缓存 | 本地可清理副本，标明服务器来源及观测时间 |

服务访问凭据不是云端个人账户。若以后需要跨设备同步关注、账号找回、私有云端记录或按用户通知/计费，再评估服务器身份与个人数据存储。

## 页面与操作

| 页面 | 数据与操作 |
|---|---|
| 关注 UP 库 | 本地关注的 UP，合并公共资料、版本与粉丝变化；本地取消关注；按需获取全部可见视频后选择关注 |
| 关注视频库 | 本地关注的视频，合并公共播放趋势与版本；本地取消关注；创建本地下载 |
| 搜索发现 | 区分服务器公共记录与平台当前发现，支持 UID/BV/链接，按能力扩展关键词搜索；显式关注或下载 |
| 下载任务 | 本地排队、进度、暂停、失败和完成，继续/取消及文件查看 |
| 本地设置 | 服务器地址、可选访问凭据、Cookie、目录、并发和本地档案 |

UP 和视频关注分别管理；关注 UP 不自动关注全部历史视频。候选默认不选，支持逐项、批量和跨页选择。个人“已关注”以本地保存结果为准，服务器是否“跟踪中”单独显示。资料尚未入公共库时显示待采集或本次平台查询，不填造历史。

指标增减为所选区间末值减首值，允许负数，样本不足显示未知。元数据版本和计数样本分别展示；服务器历史元数据不代表有对应历史媒体文件。

### 本地关注与公共采集申请

1. 用户关注目标，Agent 先保存本地列表项。
2. 查询公共目标状态，已跟踪则复用，不反复触发即时采集。
3. 未跟踪时提交目标标识，服务器校验和去重；未知目标先查询成功，再入库并加入跟踪。
4. 接受入队、验证成功、正在跟踪和拒绝分别显示；失败或超时不删除本地关注，未确认前不伪报公共采集成功。
5. 取消关注只影响本地；未发出的申请可以取消，已经接纳的公共任务不随其撤回。

有记录但未跟踪也需要按服务器策略处理，不能因为记录存在就认为已跟踪，亦不能让普通申请绕过管理员暂停/拒绝名单。并发申请只产生一个公共目标。合作投稿按视频标识处理，保存实际作者，不强行改写成来源 UP。

### 跟踪作者的新投稿

Agent 不运行本地周期跟踪。未来服务器可在自身可访问范围内增加公共自动发现规则，不使用用户本地 Cookie，也不承诺获取受限或已删除投稿。客户端“获取全部视频”始终是用户发起的按需任务。

## 离线、重启与同步

| 情况 | 行为 |
|---|---|
| 网页关闭 | Agent 继续已提交任务 |
| Agent 停止或设备关闭 | 公共服务器继续采集，本地任务等待重启恢复 |
| 服务器断连 | 个人关注仍可保存和查看；缓存显示更新时间；采集申请等待重连；有效 Cookie 下可发现和下载 |
| 本地取消关注 | 其他人的关注与服务器公共采集不受影响 |
| Cookie 失效 | 平台能力等待更新，公共资料查询按服务策略继续 |
| 服务访问凭据撤销 | 受限操作被拒绝，本地关注、文件和平台登录保留 |

近期先按需读取公共记录及核对采集状态；后续如做公共事件增量读取，由 Agent 按本地关注过滤通知，不把私人订阅清单交给服务器。扫描、申请和下载状态可持久化，不等于长期平台跟踪。

## 本地下载与评论扩展

### 视频下载（近期目标，尚未实现）

从个人视频库或发现结果显式创建任务，选择目录、可获取清晰度和分 P，保存进度并支持暂停、继续、取消、失败重试和重启恢复。上游支持时才续传，地址过期重新解析；音视频合并需说明本地工具依赖，未完整文件不能标完成。

下载直接从平台到本地，是否下载、目录和文件与服务器无业务关联；下载本身不自动申请公共跟踪。当前可访问媒体不等于服务器保存了历史版本的媒体。

### 评论与弹幕（后续）

分别作为独立本地文件任务，关联视频/分 P，保存范围和检查点，标记部分结果，不上传服务器。视频完成不代表评论和弹幕也已保存。

| 现有本地 API | [10 个接口](agent/README.md#api-接口) | 继续保持原有能力 |
| 8182 查询与采集 | 已有 HTML 库/详情/版本、JSON 指标/状态和单个/批量提交 | 已有接口直接复用，缺少 JSON 的页面补输出，状态补按 ID 查询，提交补普通客户端准入与幂等 |
| 个人关注库、公共请求与视频下载 | 尚未实现 | 本地存储与库页面，公共状态合并，下载任务 |

接口草案与访问控制见 [协作设计](../docs/client-server-architecture.md#api-分层)。普通客户端只查询和申请采集，不能删除公共历史、停采目标或修改全局间隔。

## 实施阶段与验收

1. 复用服务器 8182 的现有读取和提交能力，补列表/详情/版本 JSON、按 ID 状态及公共提交准入与去重，不另建查询服务。
2. Agent 本地关注存储、UP/视频库，按标识合并公共历史，添加与取消只以本地列表为准。
3. 按需发现、公共申请对账和本地视频下载、校验及恢复。
4. 后续评论、弹幕和本地备份/档案；云端个人账户仅在出现私有云端能力需求时再评估。

验收：多人本地关注互不影响；公共目标不重复；已有目标不被重复立即刷新；有记录未跟踪不误判；未知目标查询成功才接纳；取消本地关注不全局停采；本地关闭后服务器继续工作；私人数据和文件不上传；服务写入受资源限制。

当前只交付 Cookie 与 ID 扫描，验证见 [现有实现](../docs/client-discovery.md#验证)。本次调整设计，后续功能完成并验证后才归档整体实现计划。
