# 客户端需求与设计

状态：已实现首个独立功能：本地 Cookie 配置与账号验证、指定 UP 主的可见投稿视频 ID 全量分页扫描、结果查看及 TXT/JSON 导出。远程记录浏览、关注管理、视频下载、评论与弹幕仍待实施。本文统一定义界面与 Agent 的需求及验收；除“当前实现与启动”外，后续章节保留整体规划，不能视为均已实现。平台级产品需求见 [PRD](../docs/PRD.md)，实施记录见 [PLAN](../PLAN.md)，模块导航见 [架构说明](../docs/architecture.md#module-navigation)。

## 当前实现与启动

需要 Go 1.26 或更高版本。在仓库根目录执行：

```powershell
cd client
go run ./agent/cmd/agent
```

打开终端输出的完整本地链接（默认 `127.0.0.1:8183`，包含本次启动的连接密钥）。粘贴已登录 B站请求的 Cookie 并验证，输入 UP 主 UID 或 `https://space.bilibili.com/{UID}`，开始扫描。输出视频标识为 BV 号；页面展示真实进度和部分结果，支持跨页查看、复制全部 ID、TXT/JSON 导出，以及停止和继续。仅保留最近一次扫描，重新扫描会替换当前任务。

浏览器界面已通过 `go:embed` 内嵌，无需启动前端开发服务或安装 Node 依赖。构建独立程序：

```powershell
go build -o bin/agent.exe ./agent/cmd/agent
.\bin\agent.exe
```

可通过 `-listen 127.0.0.1:8183` 和 `-data data` 指定端口及本地目录，禁止监听非回环地址。Windows Cookie 使用当前用户的 DPAPI 加密保存到 `data/cookie.protected`；其他平台暂只在进程内保留 Cookie，退出后需重新导入。扫描结果与续页位置逐页保存到 `data/scan.json`；刷新或关闭网页不会取消任务，重启 Agent 后可继续未完成任务。

本期采用手动导入 Cookie；普通网页不能直接读取 B站域名的登录 Cookie，自动读取需浏览器扩展及授权，留待后续。平台限流、风控、账号失效、分页停滞或数量变化时保留结果并标记不完整；“全部”仅指这次登录态下投稿接口可枚举的范围。实现、API、验证与具体边界见 [客户端发现技术说明](../docs/client-discovery.md)。

## 产品目标与职责

服务器长期跟踪 UP 和视频，保存资料版本、粉丝与播放量历史。本地 Agent 读取这些记录、提供按需搜索发现、提交关注操作，并直接从平台下载视频到本机。Agent 不运行本地长期跟踪任务。

| 部分 | 职责 |
|---|---|
| 远程服务器 | 持久化关注和采集任务，持续记录 UP / 视频、指标和版本，提供受鉴权 API |
| 本地 Agent | 远程库与详情查询、按需搜索发现、关注交接、本地下载和必要状态保存 |
| 浏览器界面 | 关注 UP 库、关注视频库、搜索发现、下载任务和设置 |
| 本地平台适配器 | 使用留在本机的 Cookie 验证账号、获取可见投稿及当前可访问媒体 |

服务器历史是权威记录，本地缓存只是副本。按需扫描可保存进度，下载可保存断点，但本地不定时追加平台指标历史。平台 Cookie、视频、评论、弹幕和本地路径不上传项目服务器。

## 运行方式与协作关系

浏览器通过同源 HTTP API 访问本地 Agent。Agent 有两类外部请求：用设备凭据向远程服务器读取历史和管理关注；用本地 Cookie 向平台按需发现和下载。目标结构与模块扩展见 [远程协作设计](../docs/client-server-architecture.md#职责)。

```text
+--------------------------------------+
| browser: libraries / discovery       |
+--------------------------------------+
                   | local HTTP
                   v
+--------------------------------------+
| Agent: remote access / local tasks   |
+--------------------------------------+
                   | HTTPS: records / follows
                   v
+--------------------------------------+
| server: tracking / history           |
+--------------------------------------+
```

平台访问单独由 Agent 发起，媒体文件直接保存本地。关闭网页不停止已提交任务，退出 Agent 只暂停本地任务；远程服务器继续采集。现有 8182 仍承担服务器管理，客户端复用它的业务和数据口径，不抓取或直接开放管理页。

## 身份、数据与状态

首期已确认为个人自用、单一工作区：Agent 无独立用户名密码体系，服务器以设备凭据鉴权，暂不建设注册登录系统；保留必要的本地状态。账号认证和是否持久化不是二选一：

- 浏览器访问 Agent：保留现有本地会话、Host/Origin 和 CSRF 保护。
- Agent 访问服务器：个人先绑定单工作区，每台设备持有可撤销的受限凭据；多人使用时在服务器登录并隔离各自的关注。
- Agent 访问 B站：使用本地 Cookie，与服务器凭据分别管理。

配置与凭据、扫描和下载进度、关注操作待确认队列需要保存；服务器响应可按需缓存并注明时间。关注关系和长期历史只以服务器为准。缓存按服务器实例及工作区隔离，可以清理重建；敏感凭据不回传网页或写入浏览器存储。

## 页面与操作

| 页面 | 数据与操作 |
|---|---|
| 关注 UP 库 | 服务器已关注 UP、资料版本、粉丝趋势与增减；关注管理；获取全部可见视频后选择关注视频 |
| 关注视频库 | 服务器已关注视频、播放趋势与内容版本；关注管理；选择本地下载 |
| 搜索发现 | 分开查询服务器记录与平台当前候选，支持 UID/BV/链接查找，按平台能力扩展关键词搜索；显式关注或下载 |
| 下载任务 | 排队、执行、暂停、失败和完成；继续、取消及本地文件查看 |
| 连接与账号 | 服务器地址和设备状态、本地 Cookie、下载目录及并发 |

两个库默认展示当前工作区的关注。关注 UP 不自动关注全部历史视频；历史候选默认不选，允许逐项、批量和跨页全部提交。搜索、发现、浏览和下载都不隐式创建关注。

版本和指标来自服务器数据库，显示真实观测时间。所选区间的增减为末值减首值，允许负数；样本不足显示未知，不填造历史。元数据版本和粉丝/播放量样本分别展示，不把每次计数变化当成新版本。

### 本地发现与远程关注

1. 读取远程关注库与详情。
2. 用户输入标识搜索，或在 UP 库点击获取全部视频，复用当前 Cookie 分页扫描；全部仅指当次登录态下可枚举的可见范围。
3. 用户选择候选，Agent 仅提交平台和目标标识及必要的幂等信息。
4. 服务器鉴权、重新查询并保存关注与跟踪任务，返回逐项确认；Agent 再更新显示。
5. 请求超时先对账，未确认前显示待提交或失败。取消关注不删除历史及本地文件。

合作投稿保留在来源 UP 的列表中，关注时由服务器保存视频的真实作者，不强行改写归属。

### 跟踪作者的新投稿

长期发现或采集规则不在 Agent 运行。未来如提供自动关注新投稿，由服务器在自身可访问范围内执行；服务器不使用用户本地 Cookie，不承诺发现它无权访问的投稿。当前客户端只提供用户发起的按需发现。

## 离线、重启与同步

| 情况 | 行为 |
|---|---|
| 网页关闭或刷新 | Agent 继续已提交本地任务，重新打开读取状态 |
| Agent 停止或设备关闭 | 服务器继续跟踪；本地任务停止，重启后从检查点恢复 |
| 服务器断连 | 显示已有缓存时间；关注操作保留待确认；有效 Cookie 下可继续本地发现或下载 |
| 平台 Cookie 失效 | 平台发现和下载等待更新，远程历史与关注接口仍可用 |
| 服务器设备凭据失效 | 阻止远程读写，本地平台登录分别管理 |

近期先按需分页读取远程记录和核对关注，不要求先实现完整事件复制系统。若后续加入增量事件同步，记录、派生任务和游标应一同落盘，下载成功不是同步确认前提；不能拿现有短期发现会话当永久游标。

## 本地下载与评论扩展

### 视频下载（近期目标，尚未实现）

从视频库或发现结果显式创建下载，选择本地目录、可获取的清晰度及分 P 范围。任务持久化进度，提供暂停、继续、取消和失败重试；地址过期重新解析，仅在上游支持时续传，完成前验证文件。需要音视频合并时明确本地工具依赖。

媒体直接由平台到本地，不经项目服务器。未完整文件不显示完成；目录和路径由本地用户控制。服务器保存的历史元数据不代表保存了相应历史媒体，下载只能获取当前仍可访问的内容。下载不要求先关注该视频，默认不自动下载所有关注内容。

### 评论与弹幕（后续）

评论和弹幕分别作为独立文件任务启用，可与视频关联但不依赖视频下载成功。保留分页或分段进度、观测范围和部分结果标识，文件只保存在本地；具体格式与平台适配后续确定。

## 实施阶段与验收

1. 服务器：设备认证、工作区权限、库/详情/版本/指标读取、关注增删及幂等确认。
2. Agent 与页面：远程客户端、关注 UP 库和视频库、按需搜索发现及候选关注交接。
3. 本地视频：下载任务、文件校验、暂停/恢复和本地文件查看。
4. 后续：评论与弹幕文件、多人账户、更完善的事件同步。

验收重点：本地退出不影响服务器采集；Agent 不维护自己的长期指标历史；关注以服务器确认为准；两个库支持真实版本和正负增长；视频下载直接落本地且失败可恢复；平台 Cookie、文件和路径不进入项目服务器；设备撤销阻止远程读写。

当前仅已交付 Cookie 与投稿 ID 扫描，测试及边界见 [现有实现](../docs/client-discovery.md#验证)。以上后续目标完成并验证后，才将整体客户端计划标记完成。
