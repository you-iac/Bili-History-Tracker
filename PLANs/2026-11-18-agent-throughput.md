## 目标与边界

重写 [压测脚本](../scripts/perf/load_test.py)，以多个 Agent 对 8181 的混合业务调用衡量服务器吞吐。依据 [remote](../client/agent/internal/remote/client.go) 和 [关注核对](../client/agent/internal/library/reconciliation.go)，覆盖双目录首页、目录、详情、状态与关注核对。默认只读、无本地缓存；可选择客户端节流或容量模式。真实首次申请、已有任务复用和批量诊断分开，不把健康检查或重复 existing 应答当作采集/落库吞吐。

## 实施方案

1. 统一测量窗口，同时运行多个 Agent；分别统计窗口内业务成功吞吐、请求吞吐和完整业务操作吞吐，停止发新请求后单独统计收尾。
2. 验证 HTTP、JSON、业务码和目标身份，记录限流、阶段、结果、失败样本与延迟，不自动重试隐藏故障。
3. 仿照 Agent 的 150ms 节流和限流冷却提供可选模式；容量模式去掉客户端节流，并明确报告区别。
4. 使用已记录资料池分散读取；首次申请使用显式目标文件，每项至多消费一次；已有任务写入/批量诊断先只读核验，不隐式 warmup。
5. 更新脚本说明与架构导航，添加本地模拟 HTTP 服务回归测试。

## 验收

- HTTP200 限流、无资料、格式/身份错误不会记作业务成功。
- 收尾完成数不计入固定窗口吞吐；报告实际耗时与收尾、成功/失败延迟。
- 混合流量使用 Agent 路径，不请求 `/`、`/healthz` 或未使用的独立指标接口。
- 申请失败的 HTTP 请求与后续状态核对恢复分别保留；批量截断不视为全部成功。
- 本地自动化回归通过；真实 VM 容量留待用户运行，不能用模拟服务推断容量。
