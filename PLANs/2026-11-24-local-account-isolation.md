# 本地多账号数据隔离（用户管理）

- 创建时间：2026-11-24 23:05（Asia/Shanghai）。
- 状态：待实施；先记录设计，不修改现有存储与账号绑定逻辑。
- 目标：未来支持本地多用户/多 B站 账号。每个 Cookie 解析出的 B站用户拥有独立数据目录，关注、设置、历史、互动缓存、扫描状态都按账号隔离；切换账号时互不串数据。
- 背景：当前是单数据目录下的 `library.json`、`history.json`、`scan.json` 和 Cookie。换 Cookie 时历史与互动缓存不隔离，存在旧账号数据参与新账号展示/自动关注的风险（见 PR #21 的账号隔离评论）。

## 设计

### 账号识别

- Cookie 验证时调用 `Login`，返回 `mid` / `uname`；
- 以 `mid` 作为账号标识；
- 未登录或验证失败时不切换目录。

### 目录结构

```text
data/
  accounts/
    <mid>/
      library.json     关注、服务器配置、互动设置
      history.json     观看历史与互动状态
      scan.json        扫描任务
      cookie.protected 该账号的 Cookie
  guest/               未登录时的临时数据（可选）
```

- 每个账号目录独立；
- 目录权限 0700；
- 服务器配置、关注、历史、互动、扫描都按账号存放；
- 删除账号只删目录，不影响其他账号。

### 切换流程

```text
保存新 Cookie
  → Login 验证
  → 得到 mid
  → 切换到 data/accounts/<mid>/
  → 加载该账号的 library/history/scan
  → 页面刷新
```

- 切换时关闭当前账号的后台循环（`RunPending`/`RunInteractions`）；
- 用新账号的 store 重新启动循环；
- 旧账号目录保留，可切回。

### 迁移

- 现有单目录数据在首次登录时归入对应账号目录；
- 迁移前备份；
- 无账号数据保留为 `guest`，不自动合并。

## 边界

- Cookie 仍只存本机，不上传服务器；
- 服务器推送仍按当前账号的关注；
- 多账号不改变服务器端“公共数据 + 私人关注”的模型；
- 不自动删除旧账号目录。

## 验收

- 账号 A/B 切换后，关注、历史、互动设置、扫描状态互不影响；
- 旧数据能迁移到首次登录账号；
- Cookie 失效或验证失败时不串到其他账号；
- 后台循环随账号切换重启；
- 测试覆盖目录切换和迁移。

## 实施顺序

1. 本文档；
2. `Login` 返回账号 ID 并暴露当前账号；
3. 账号目录与 store 切换；
4. 首次登录迁移；
5. 切换时重启后台循环；
6. 多账号验收。
