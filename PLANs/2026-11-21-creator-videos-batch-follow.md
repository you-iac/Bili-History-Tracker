# UP 详情页批量关注本页

- 创建时间：2026-11-21 00:40（Asia/Shanghai）。
- 状态：待实施；本项先完成文档与接口设计，不修改业务代码。

## 目标

在 UP 主详情页的“未关注投稿”列表中增加“关注本页”按钮：按当前排序和当前页内容批量关注，避免逐条点击。

## 现状

- `client/frontend/creator-videos.js` 只提供单条关注按钮，逐条调用 `onAdd`，每点一次都会触发列表刷新。
- 排序由 Agent 对已获取集合排序，`ValidSort` 已支持 `published`、`views`、`popular`、`hot`、`added` 等；本项不新增排序。
- 分页固定 20 条，本项不改变分页密度；密度分页由 `feat/creator-videos-page-size` 单独处理。
- 服务器端 `POST /api/ingest/videos` 是另一条批量导入链路，与本项无关，不复用。

## 交互

1. “未关注投稿”列表工具栏显示“关注本页（N）”，N 为当前页尚未关注的视频数；N 为 0 时按钮禁用。
2. 点击后提交当前页未关注 ID；排序、搜索、翻页后按钮数量随当前页更新。
3. 成功项从“未关注”视图移除，计数更新；失败项保留并提示，可重试。
4. 单条关注按钮保留，行为不变。
5. 不弹二次确认；按钮文案已明确“本页”，误触成本可控。若后续需要，可加确认。

## 实现方式

不新增后端批量接口，后端保持“一次提交一个”。前端对当前页未关注 ID 逐个调用现有单条接口：

```text
POST /api/follows
{ "kind": "video", "id": "BV1xx411c7mD" }
```

流程：

1. 收集当前页 `result.items` 中未关注的 ID；
2. 串行提交，上一项完成后再发下一项；
3. 每项之间保留短延迟（如 100 ms），避免瞬时并发；
4. 单项失败记录后继续，不中断整批；
5. 全部结束后刷新列表，失败项提示并可重试；
6. 按钮显示“处理中 x/N”，处理中禁用，防止重复提交。

前端汇总结果（仅展示，不落库）：

```json
{
  "added": 12,
  "existing": 2,
  "failed": 1,
  "results": [
    { "id": "BV1xx411c7mD", "status": "added" },
    { "id": "BV1zz411c7mF", "status": "failed", "error": "本地关注写入失败。" }
  ]
}
```

约束：

- 当前页最多 20 条（密度分页后 12–30 条），不需要额外批量上限；
- 复用单条接口，后端不新增路由；
- 已关注项前端直接跳过，不请求；
- 单项失败不影响其他项。

## 边界

- 只影响当前页，不是全部未关注投稿；
- 不改变服务器端批量导入与限流；
- 服务端“一次一个”的写入语义不变，不在后端做批量事务；
- 关注后不自动触发服务器历史同步，仍由现有同步逻辑处理；
- 不新增排序逻辑，只复用现有 `sort` 参数。

## 验收

- 当前页全部未关注时，一次请求完成关注；
- 已关注、重复 ID 不重复写入；
- 失败项有明确提示且可重试；
- 单条关注按钮仍可用；
- 空列表、超过 50 个 ID、非法 kind 返回 400；
- `go test ./...`、前端 `node --test` 通过。
