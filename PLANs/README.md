# 项目计划

全部计划按“一项计划一个 Markdown 文件”保存在本目录，未完成和已完成计划放在一起。浏览目录即可查找各项计划；状态、方案和验证以对应文件为准，不维护需要随状态反复调整的集中清单。

## 创建与维护

- 文件名采用 `YYYY-MM-DD-简短主题.md`，使用原创建日期和稳定主题；日期无法确认时用 `undated-简短主题.md`。同日不同计划使用不同主题，不因完成而改名或移动。
- 文件顶部写标题、创建时间和当前状态，正文保留目标、范围、实施方案及验收条件。北京时间统一为 `Asia/Shanghai`，精确时间格式为 `YYYY-MM-DD HH:mm`；历史记录只能确认日期时标明精度，无法确认时写“未记录”，不得用迁移或提交时间代替。
- 只修改正在推进的计划文件；相关需求、技术文档直接链接该文件，无需为每次新增或完成计划更新本说明。
- 本目录中的相对链接从 `PLANs/` 起算，例如 `../docs/architecture.md`；计划之间直接链接文件名，不依赖列表顺序。

## 完成方式

只有目标实际完成且必要验证通过，才在原文件最上方、标题之后添加 `## 完成摘要`。摘要记录已完成状态、原创建时间、完成时间，并用一段话概括最终改动、关键边界、验证结果和相关引用。

原方案及实施记录完整保留在摘要下面，不用摘要替换正文，不压缩、删除或迁移原方案。当前状态以顶部摘要为准，下方原状态保留为历史；部分完成、待评估或仍有未完成验收项时，不添加完成摘要。

示例结构：

```markdown
# 计划标题

## 完成摘要

- 状态：已完成。
- 创建时间：沿用原记录。
- 完成时间：实际完成时间（Asia/Shanghai）。

一段话说明最终改动、关键边界、验证结果及相关引用。

## 原计划

此处保留原有创建时间、状态、目标、方案、验收及实施记录。
```

## 历史迁移

原集中计划文件中的 6 项未完成计划和 10 项已完成计划均已拆分到本目录，保留原有时间及内容，并修正相对链接。历史已完成项在迁移前只剩完成摘要，按已有内容保存并注明，未补造原始方案；历史验证结论不代表当前环境已经重新验收。
