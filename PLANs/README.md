# 项目计划

全部计划按“一项计划一个 Markdown 文件”保存：未完成计划放在本目录，已完成计划移入 [archive/](archive/README.md)。状态、方案和验证以对应文件顶部的当前记录为准，不维护需要随状态反复调整的集中清单。

## 创建与维护

- 文件名采用 `YYYY-MM-DD-简短主题.md`，使用原创建日期和稳定主题；日期无法确认时用 `undated-简短主题.md`。同日不同计划使用不同主题，完成时保持原文件名并移入 `archive/`。
- 文件顶部写标题、创建时间和当前状态，正文保留目标、范围、实施方案及验收条件。北京时间统一为 `Asia/Shanghai`，精确时间格式为 `YYYY-MM-DD HH:mm`；历史记录只能确认日期时标明精度，无法确认时写“未记录”，不得用迁移或提交时间代替。
- 维护正在推进的计划及必要的关联引用；相关需求、技术文档直接链接计划的实际路径，无需为每次新增或完成计划更新本说明。
- 本目录中的相对链接从 `PLANs/` 起算，例如 `../docs/architecture.md`；归档计划从 `PLANs/archive/` 起算，例如 `../../docs/architecture.md`。活动计划引用归档计划使用 `archive/文件名.md`，归档计划引用活动计划使用 `../文件名.md`，不依赖列表顺序。

## 完成方式

只有目标实际完成且必要验证通过，才在原文件最上方、标题之后添加 `## 完成摘要`。摘要记录已完成状态、原创建时间、完成时间，并用一段话概括最终改动、关键边界、验证结果和相关引用。

原方案及实施记录完整保留在摘要下面，不用摘要替换正文，不压缩或删除。完成摘要写好后，将整个文件移入 `PLANs/archive/`，保持文件名及已有创建、完成时间不变；同步修正文件内部相对链接和仓库中指向旧路径的引用，并检查链接目标存在。

当前状态以顶部摘要为准，下方原状态保留为历史；部分完成、待评估或仍有未完成验收项时，不添加完成摘要、不归档。不能仅凭正文中的“已完成”字样判断整项计划已完成。

示例结构：

```markdown
# 计划标题

## 完成摘要

- 状态：已完成。
- 创建时间：沿用原记录。
- 完成时间：实际完成时间（Asia/Shanghai）。

一段话说明最终改动、关键边界、验证结果及相关引用。

## 原计划

此处保留原有创建时间、状态、目标、方案、验收及实施记录。
```
