## 目标

按用户要求，重点测量按 ID 读取一个创作者或视频的现有详情接口；保留混合业务测试，增加独立的无数据库健康检查基线，以辅助区分业务查询与传输开销。不更换通信协议，也不修改后端业务读取逻辑。

## 实施与验收

1. 默认读取场景改为 detail，支持按类型筛选和固定一个 ID；固定 ID 直接预检详情，不自动发现目录或发起采集。
2. HTTP 与操作统计均区分 creator/video，明确默认读取当前资料、30日指标与第一页版本，固定 ID 与多 ID 随机测试分开解释。
3. health 场景独立运行且不读取数据库资料池，不能混入详情吞吐；记录响应体大小与字节吞吐，不能将不同大小响应的差额直接归因于 HTTP 协议。
4. 本地模拟服务验证默认场景、类型隔离、固定 ID、缺资料失败、健康检查无数据库路径以及连接复用。
5. 更新 [使用文档](../scripts/perf/README.md) 和 [架构导航](../docs/architecture.md)，说明先测并发阶梯与性能剖析，再决定是否有协议优化需求。

实际 VM 吞吐由用户复测；模拟服务只验证逻辑。
