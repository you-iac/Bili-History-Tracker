## 目标与范围

新增独立的 `backend/internal/publicapi` 模块，集中承载 Agent 使用的公开资料查询、目标状态及跟踪申请。8181 保留原有实时平台查询 API，并统一执行简单流量限制；8182 只服务本地管理页面，不继续对 Agent 提供协议。不引入访问令牌、账号、设备注册、IP 配额或复杂流量管理。

## 实施方案

1. 将 `admin/client.go` 的数据库 JSON 读取和客户端目标申请迁至 `publicapi`；两端共享现有 `storage`、`tracker`，不复制数据库或调度器，不改变采样口径。
2. 8181 显式注册客户端路由，统一返回 JSON；保留 `/api/v1/platforms/...` 的原响应。不得挂载完整 `admin.Handler()`，不得暴露管理表单、停采、修改间隔、日志或后台批量导入。
3. 全部 8181 请求共用一个进程级入口限制，默认每个滚动一秒最多 20 次，并以相同数值限制尚未完成的 HTTP 请求，避免慢请求累积；只保留一个流量参数 `BHT_API_RPS`。超限直接返回 429 和 `Retry-After: 1`，不排队，不按 IP 建表，不信任转发头。保留查询超时和 tracker 原有采集并发限制。
4. 保留 `POST /targets` 单目标 JSON；额外支持 `{"targets":[{"type":"video","id":"BV..."}, ...]}`。默认只处理原始数组前 10 项，由 `BHT_API_BATCH_MAX` 调整；按原始位置截断，后续项不校验目标、不请求上游、不入库、不排队。整个 JSON 仍须语法正确且不超过 64 KiB。响应明确给出逐项结果、处理数量及忽略数量，不能把批量 HTTP 200 当作所有项已关注。批量按顺序执行，共享 20 秒处理预算，不启动无限 goroutine。
5. 8182 页面取消 `Accept: application/json` 的客户端输出，JSON 目标提交返回 415；原 `/api/*` 路由移除。图表、状态轮询和作者视频导入等管理页面自身使用的请求改为 `/manage/...`，仅作为管理页面内部交互保留，不接入 Agent 或 8181。
6. Agent 保留单目标提交、成功确认和退避逻辑，修改连接提示与文档，指导用户将服务器基地址改为 8181。不得猜测、自动重写已有自定义端口或 SSH 隧道地址。本次不实施[关注状态对账计划](2026-11-16-agent-follow-reconciliation.md)。

## 验收

- 8181 的库、详情、版本、状态及单目标提交可用，既有实时查询响应兼容；读取已记录资料不请求 B 站。
- 8181 无后台页面、日志、管理命令或导入能力；表单无法借 `/targets` 改间隔或触发后台刷新。
- 8182 不提供 Agent JSON 协议、`/api/*` 均返回 404；HTML 管理、趋势图、状态轮询、作者视频发现/导入仍可用。
- 并发访问的滚动一秒限额、慢请求上限、429/Retry-After、不同接口共用限额、完成/错误后的计数释放有确定性测试。
- 批量首 N 项截断、无效项占位、重复目标、暂停目标、混合成功失败、忽略项无副作用、请求体上限、处理超时和单目标响应兼容有测试。
- 两个 Go 模块完成测试、vet、构建；运行客户端 pnpm lint/test、后台 Node 测试及隔离数据库的真实 HTTP 联调，不访问或修改用户数据库。
- 同步模块说明、架构导航、当前客户端接入和管理文档。计划完成状态以实际验收为准，不将未实施的令牌、长期任务总预算或公网抗 DDoS 视为已完成。
