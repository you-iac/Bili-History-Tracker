## 目标与交付范围

作者详情默认展示 Agent 获取的当前资料、服务器记录 seq 与跟踪信息、粉丝曲线及本地已关注视频。正常服务器读取目标为 2 次 SQL；平台当前资料失败时允许额外 1 次 SQL 读取服务器最后保存资料。历史版本与对比按需加载。当前资料获取与回退契约支持作者、视频，首期页面改造限作者详情及其中的视频卡片，不自动扩展为全站重构。

本计划记录待实施任务；建立设计文档不等于实现完成。维持数据库、采集和旧接口兼容，不删除已有版本、统计或本地用户数据。

## 已确认的设计决策

- 平台当前元数据优先由 Agent 查询，历史采样、服务器版本及公共跟踪状态由服务器提供。
- 平台失败后再读服务器最后保存资料；服务器也失败时保留原有本地缓存，无缓存显示不可获取，不猜测目标已删除。
- 平台资料、服务器回退、历史曲线分别保存来源与观测时间；平台即时计数不写进服务器曲线，不附会服务器 seq。
- 本地视频列表由 Agent 筛选排序分页，打开作者详情不自动逐个同步服务器摘要或核对/申请视频任务；已有后台关注核对保留独立职责。
- 默认不查历史版本总数、版本列表、当前/上一版对比；不复用重型旧详情作为新回退入口。
- 2/3 次 SQL 是基础正常/回退路径预算；图片、用户主动更新、历史展开及后台采集分别统计，不承诺端到端耗时。

## 待实施任务与依赖

### T1：冻结契约与测量基线

- [ ] 按设计冻结 Agent 当前资料、服务器基础历史、最后保存资料、版本列表和指定快照的路径、字段与错误契约；保留旧协议兼容，明确不支持新能力的处理。
- [ ] 明确平台/服务器缓存的独立结构、来源枚举、观测/检查时间、服务器地址/代际、绑定 seq 和回退原因；制定旧缓存兼容读取方式。
- [ ] 用隔离数据库记录原基础请求与整页请求；区分直接 HTTP 压测、真实 Agent 页面与后台核对，记录 SQL/请求数及延迟口径。
- [ ] 校验 Agent 实际可调用的平台元数据能力；平台失败、字段缺失与错误身份均纳入桩响应。默认公开资料不依赖扫描 Cookie。

验收：形成可测试的请求/响应样例和基线记录，设计文档与公共协议一致；尚未获取真实平台证据时明确列为待验收，不阻止隔离实现。

### T2：服务器轻量历史及资料回退（依赖 T1）

- [ ] 一条目标查询读取作者 seq、资料观测时间和任务状态，覆盖仅任务、仅作者、两者都无及作者 seq=0 占位；从 tracker 内存补 running，不重复查询 Content/Catalog。
- [ ] 一条目标/时间范围查询读取粉丝采样，保留 UTC 日、7/30/90/all、空值/缺失/截断语义。
- [ ] 增加独立只读的最后保存资料入口：一条 SQL 关联当前表与当前版本，返回绑定的 seq、资料观测时间和快照时间；不得触发上游查询或任务写入。
- [ ] 增加按需版本列表及指定快照的独立读取，不再借用完整详情获取某版；按设计采用有界续页，基础页不读取总数。
- [ ] 补状态、业务错误和 HTTP 输入校验测试；使用实际 SQLite/查询计数证明正常 2 次、回退额外最多 1 次，校验无全平台窗口和无视频汇总。
- [ ] 对精确查询执行 EXPLAIN QUERY PLAN，确认现有索引可用；确有证据才调整索引，不预设必须迁移数据库。

验收：成功、无资料和内部读取失败均符合预算与语义；旧 API、管理台及采集测试保持通过；资料与状态不冒称事务一致。

### T3：Agent 当前资料、缓存与回退（依赖 T1、T2）

- [ ] 实现作者/视频当前元数据的有界平台读取，校验规范 ID、响应身份、错误与未知计数；复用适合的适配逻辑，不通过服务器中转平台请求。
- [ ] 先展示缓存，平台按有效期读取；平台失败才调用服务器最后保存资料；服务器失败保留本地缓存，无缓存返回明确无资料分支。
- [ ] 平台当前资料与服务器历史并发独立处理；单分支失败不阻止另一分支成功展示，不将历史失败误认为平台失败。
- [ ] 实现独立缓存、在途合并、超时、失败退避、取消、身份与代际检查；设计初值为有效期 5 分钟、失败退避 1 分钟、平台 8 秒、回退 5 秒，验证后记录最终值。
- [ ] 回退资料与平台成功缓存不混写；切服丢弃旧服务器数据，身份匹配的平台公开缓存可复用；落盘失败保留已取得结果并提示。
- [ ] 当前图片从平台或回退资料获取地址，沿用 CDN 白名单；当前图片加载不再间接请求旧完整详情。

验收：平台成功/失败 × 服务器有记录/无记录/不可达 × 本地有无缓存的组合通过；含已无法从平台查询的作者和视频桩场景，不依赖真实删除操作。

### T4：作者页面与本地视频区（依赖 T2、T3）

- [ ] 页面分开呈现当前资料来源/时间、服务器最新 seq/观测时间、跟踪状态、粉丝曲线和各自错误；seq 不标为历史版本总数。
- [ ] 初次打开及时间范围切换不自动读版本列表、当前快照或上一版；用户展开历史、选版或比较时才读取所需内容。
- [ ] 视频区默认从本地关注、归属、扫描缓存组成列表，保留合作投稿来源；取消打开页面即逐项服务器摘要同步的链路。
- [ ] 设计并实现显式视频资料刷新或有界后台更新，不因打开 UP 页刷新所有视频；缺历史增长时显示未知，保留本地筛选排序分页。
- [ ] 覆盖慢平台、快速切换 UP、切服、取关重关注、缓存先展示及局部失败，旧结果不覆盖新页面；移动端不隐藏必要的来源和时间提示。

验收：页面正常路径不读取当前版本 payload，不发历史快照请求；平台失败时按需回退可展示服务器保存资料；视频列表的单纯浏览不新增服务器请求。

## 最终验收清单

- [ ] 作者基础历史请求恰为目标上的 2 次 SQL，无目录计数、重复 Content、版本列表或非目标聚合；平台失败的独立服务器资料回退额外最多 1 次。
- [ ] 平台无法查询的目标，只要服务器有成功记录，仍能展示服务器保存资料并标时间；seq=0 占位不算成功资料。
- [ ] 平台查询成功但粉丝/播放数缺失保持未知；平台失败不等于已删除，跟踪读取错误不伪造任务缺失，暂停不自动恢复。
- [ ] 平台当前值、服务器版本和历史曲线来源清晰；没有即时值污染历史、错误 seq 绑定或切服污染。
- [ ] 打开详情不自动查询版本历史、不逐项刷新本地视频、不扫描平台投稿；显式操作和独立后台工作另计。
- [ ] 旧协议、采集、私人关注和历史数据兼容；正常与回退的查询预算、功能及端到端性能均有验证记录。
