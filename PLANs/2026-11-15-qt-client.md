# C++ + Qt 一体化桌面客户端重构

- 创建时间：2026-11-15 10:44（Asia/Shanghai）。
- 状态：待实施；已确认未来客户端采用 C++ + Qt，本次只记录计划，不启动重写。
- 目标：将现有 Go Agent + 浏览器客户端逐步迁移为一体化桌面应用，界面与本地业务通过应用内调用协作，日常使用不需要浏览器或本地 HTTP 连接密钥；公共服务器继续使用现有 Go 实现和 HTTP API。
- 范围与边界：重写客户端界面与本地业务，保留现有需求、服务协议和数据归属；不因桌面化增加公共服务器用户账户，不将私人关注、Cookie或云盘凭据交给公共服务器。现有 `client/` 继续可运行，Qt 版本通过验收后再替换，不提前删除或移动代码。

## 实施步骤

1. 确认目标平台、Qt版本、编译器与CMake构建方案，制作小型界面原型后选择 Qt Widgets 或 Qt Quick/QML，明确应用核心、界面、平台适配、存储与远程客户端的边界。
2. 优先实现现有能力对等：本地UP/视频关注增删、搜索与分页、服务器连接、目标提交、资料/指标/版本及快照读取，以及 Cookie验证、投稿扫描、停止/继续与导出。
3. 设计后台任务生命周期、取消和进度通知，明确关闭窗口、托盘驻留和完全退出的行为，避免网络或文件任务阻塞界面；本地关注与公共跟踪继续分状态显示，本地取消不停止公共采集。
4. 提供旧数据导入与迁移预览：保留 `library.json` 关注和服务器配置，评估扫描检查点兼容性；Cookie依系统保护能力迁移，无法安全迁移时重新导入，不将DPAPI文件当作通用跨设备凭据包。迁移先备份，失败可回滚，不自动重放采集申请或下载。
5. 完成安装/更新、依赖打包、数据目录和诊断支持，验证后切换默认客户端入口，再处理旧实现的归档或移除。下载、完整数据管理、评论/弹幕及自选云盘仍按各自计划分阶段交付，不作为首次Qt替换的隐含要求。

## 验收

- 单一桌面入口可完成现有关注、服务器读写和扫描流程，无需浏览器；任务和界面生命周期明确，重启可恢复必要状态。
- 本地数据迁移保留个人关注与配置，凭据不泄漏，失败不覆盖原数据；断网保留缓存和关注，重复提交不改公共调度，取消只影响本地。
- 补充核心业务、远程协议、数据迁移和任务生命周期测试，执行桌面交互、目标平台构建与安装验证；同步模块注释、架构导航、需求和使用文档。必要验证完成前不将本计划标记完成。
