## 目标与边界

1. 本地 B站适配器读取单个 UP/视频的当前名称、图片、粉丝/播放数量和发布时间；Cookie 留在 Agent，保留固定地址、身份校验、限流、缓存、取消与错误脱敏。
2. 每页关注目标的历史变化使用有界批量接口，只查这些 ID 的指标采样；本地查询失败的 ID 才请求服务器轻量资料兜底，不再逐项调用目录或完整详情。
3. 当前详情也使用本地资料和服务器历史组合；指定版本的快照严格来自服务器历史，不能用当前 B站资料冒充历史内容。
4. UP 卡片播放合计采用用户确认的“本地已关注视频”口径；投稿统计同样只使用本地已有记录，缺失与真实零值分开，不扫描或自动关注全部投稿。
5. 公共资料池的枚举/搜索仍需服务器提供已记录目标目录；本地私人关注与服务器跟踪状态保持独立，既有申请和后台核对职责保留。
6. 不改写已暂存的上一轮优化，不提交、推送、合并或部署；不访问真实 Cookie、用户数据库或运行中的服务。

## 实施与验收

- 新增本地资料读取和服务器目标级批量历史、轻量兜底、历史专用入口；保持未知/占位/无历史/快照不存在及 HTTP200 业务错误语义。
- 覆盖一页多个目标仅一次批量历史请求，成功本地读取不请求服务器资料/目录/详情；部分失败只为失败 ID 兜底，两个来源都失败时保留旧缓存和错误。
- 覆盖页内去重与上限、身份/平台隔离、Cookie不外传、图片白名单、429冷却、并发合并、切服/取消重关注隔离、空采样与负增长。
- 覆盖本地汇总随关注变化、已关注视频在 UP 详情中的刷新、当前资料与历史快照隔离及缓存重启。
- 同步包/文件注释、架构导航、API 与本地数据说明；执行两模块 Go test/vet/build、前端 lint/test、必要的隔离 HTTP 联调和文档链接检查。
- 目标实际完成且必要验证通过后添加完成摘要，保留原方案与实施记录并归档。

## 实施记录

- 起始工作区已有上一轮详情优化的暂存改动，本次保持其暂存状态，不重置或覆盖。
- 用户已确认 UP 播放合计为本地已关注视频的播放合计，不能标成服务器已记录范围或 B站账号总播放。
- Agent 新增固定 B站接口、身份校验、Cookie 本地持有、并发上限、短期缓存、429 冷却和图片白名单；资料错误会保留旧缓存并向界面暴露，不用零值冒充未知值。
- 服务端新增目标级批量指标、轻量资料兜底、历史读取及轻量目录投影；普通目录排序不再读取变化表，热门/增长排序只在明确选择时读取对应 7 日采样。
- 客户端每种目标一页只发一次指标批量请求，兜底 ID 仅包含本地失败或资料不完整项；当前详情与历史快照分别读取，切换服务器、取消后重关注及并发刷新均按会话代次隔离。
- 本地 UP 汇总仅遍历关注库：播放量为已关注视频当前播放量之和，近 7 日投稿数和最近投稿也只使用本地已知视频；缺失数据保持未知。
- 隔离基准中，18 个条目的旧目录摘要读取中位约 114.84 ms、约 356.5 KB 分配；新的单次历史批读中位约 0.373 ms、约 21.8 KB 分配。两者职责范围已经不同，该数据不包含本地访问 B站的网络耗时，也不作为真实部署延迟结论。
