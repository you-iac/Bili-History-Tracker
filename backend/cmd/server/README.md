# cmd/server 入口

唯一组装点：读环境变量、创建对象、启动两个服务和一个调度器。8181通过`publicapi.New`组装Agent协议及原实时API，共用全局限额；8182只提供本地管理。配置、批量与应答见[公共接口说明](../../../docs/public-api.md)。

> 与 [main.go](main.go) 的包注释保持一致；架构总览见 [docs/architecture.md](../../../docs/architecture.md)。

## 输入 / 输出 / 边界

- **输入**：`BHT_*` 环境变量、操作系统的中断／终止信号（Linux 上为 `SIGINT`、`SIGTERM`）。
- **输出**：两个监听端口、一个调度 goroutine、一个 SQLite 文件。
- **它不认识**：业务规则、SQL、B站字段；只负责创建、连接和生命周期。

Linux 的 `SIGTERM` 与 Ctrl+C 的 `SIGINT` 共用现有停机入口。当前入口会取消主 context、尝试关闭 HTTP 服务，再由 defer 关闭管理任务、日志和数据库；尚未显式等待调度器与 `RunNow` 异步任务结束。收到停机信号不等于后台工作已经完成，详见 [架构说明](../../../docs/architecture.md#启动时如何组装服务) 与 [BACK-SHUTDOWN 评审](../../../PLANs/2026-11-17-backend-api-freeze-review.md#back-shutdownlinux-sigterm-与后台退出链路不完整)。

## 环境变量

| 变量 | 默认值 |
|---|---|
| `BHT_ADDR` | `127.0.0.1:8181` |
| `BHT_ADMIN_ADDR` | `127.0.0.1:8182` |
| `BHT_API_RPS` | `20`（1至10000） |
| `BHT_API_BATCH_MAX` | `10`（1至100） |
| `BHT_DB` | `data/bht.db` |
| `BHT_QUERY_LOG` | 数据库同目录 `query.log` |
| `BHT_BILI_COOKIE` | 空 |
